## [1.0.1-beta2] - 2026-06-29 - frontend guidance and documentation

Обновление фронтенда и документации. Миграция базы не требуется.

- Dashboard: Traffic statistics теперь включает выбор часового пояса с дефолтом из browser timezone; выбор сохраняется в `localStorage`, подписи графиков используют формат `YYYY-MM-DD HH:MM`, а выбранный часовой пояс отображается в KPI metadata.
- Настройка inbound: формы добавления inbound теперь показывают рекомендации с учетом протокола через явные действия в режиме создания и подсказки у полей. VLESS и другие поддержанные протоколы получают безопасные presets только после клика Apply inbound recommendations; формы редактирования сохраняют существующие пустые значения.
- Безопасность inbound: Shadowsocks и Sudoku credentials генерируются при создании новых inbound, ShadowTLS password генерируется только для version 2, а TLS/Reality templates фильтруются так, что Reality показывается только для VLESS и Trojan.
- Локали и тесты: новые подсказки inbound-рекомендаций добавлены во все поддерживаемые локали UI, а тесты покрывают parity локалей, recommendation helpers, генерацию inbound credentials и совместимость TLS template.
- Документация: README теперь описывает поведение selector часового пояса для Dashboard Traffic statistics и обновляет список поддерживаемых протоколов по repository capability/configuration documentation.

Полные release notes: [`.github/RELEASE_NOTES_v1.0.1-beta2.md`](.github/RELEASE_NOTES_v1.0.1-beta2.md).

## [1.0.1-beta1] - 2026-06-28 - hardening

Hardening-релиз. Миграция базы не требуется.

- Shell: убран `eval` из установщика произвольной версии; `s-ui uri` больше не обращается к внешним IP-сервисам; все позиционные аргументы закавычены; `read -r` повсеместно; пути с тильдой исправлены.

- Cron-задачи пробрасывают контекст и отменяются при остановке; повторы WARP учитывают отмену контекста; инициализация соли IP-монитора защищена от гонок; добавления protocol coverage из предыдущей волны изменений также входят в этот релиз.
- Имена авто-зарегистрированных клиентов проверяются на уникальность в базе перед использованием.

## [1.0.0-beta7] - 2026-06-23 - сессии и extended-протоколы в обоих интерфейсах

Pre-release. Дополнение к v1.0.0-beta6. Ручная миграция базы не требуется.

- Проверка обновлений в веб-панели теперь обращается к `deposist/s-ui-x-extended`, а не к старому репозиторию `deposist/s-ui-x`.

## [1.5.10-beta1] - 2026-06-23 - исправления производительности и безопаснее большие базы

Первая бета линейки 1.5.10. Ручная миграция базы, API или конфигурации не требуется. Полный Go suite, Go vet, frontend lint, frontend build и frontend unit tests проходят.

- Графики статистики теперь готовят большие выборки через один проход bucket assignment после сортировки, вместо повторного сканирования всех строк для каждого bucket и направления. Запись статистики использует явные SQLite-safe batch-вставки.
- `/api/load` теперь читает settings для полного reload через один snapshot и параллельно читает независимые сущности.

## [1.5.7-beta7] - 2026-06-06 - hardening по итогам независимого ревью; удалены плановый синк и удалённый импорт 3x-ui

В эту бету входит **удаление планового синка / удалённого импорта 3x-ui** плюс набор
**малорисковых фиксов и hardening** по итогам свежего независимого аудита качества
кода, оптимизации и безопасности. Новых функций нет, **ручная миграция не требуется**.
Удаление 3x-ui меняет существующее поведение (Ломающие изменения ниже); фиксы из ревью
ничего не ломают.

Импорт из 3x-ui сведён к **разовой загрузке локального файла `.db`**.
Периодический **плановый синк** и **удалённый импорт по запросу** (затягивание
из работающей 3x-ui по SSH/HTTP) удалены вместе со всей обвязкой: источники
SSH/HTTP/file, SSRF-защищённый удалённый клиент, хранилище SSH host-key (TOFU) и
шифрование сохранённых sync-профилей на диске.

**Ломающие изменения**
- **Планового синка больше нет.** Страница расписания «3x-ui Sync», sync-профили
  и фоновая cron-задача удалены; любое ранее настроенное расписание после
  апгрейда перестаёт работать. Таблицы `xui_sync_profiles` и `xui_known_hosts`
  автоматически удаляются при первом старте - без ручных действий.
- **Удалённого импорта больше нет.** Эндпоинты `POST /api/import-xui/remote/*` и
  `/api/import-xui/sync/*` удалены. Импорт теперь только из загрузки файла:
  `POST /api/import-xui[/plan|/apply|/rollback]` и `GET /api/import-xui/reports`.
- **CLI:** команда `s-ui sync-xui` и флаги `import-xui --remote` / `--schedule`
  удалены; `s-ui import-xui --src <x-ui.db>` (локальный файл) остаётся.
- **API-токены:** scope `xui_remote` удалён и больше не является допустимым.
  Перевыпустите такие токены с подходящим scope.

### Безопасность и приватность (фиксы из ревью)

- **Логин больше не выдаёт, существует ли имя пользователя** - путь «не найдено»
  выполняет ту же bcrypt-работу, что и неверный пароль (закрыт тайминг-оракул
  перечисления админ-логинов).
- **Креды в URL маскируются в логах** - `user:pass@host` в любом логируемом URL
  редактируется в свободном тексте, а не только под секрет-именованным ключом.
- **Cookie сессии - Secure по умолчанию** в session store (боевые login/CSRF-потоки
  уже выставляют это явно).
- **Refund отклоняет повреждённые заказы** - оплаченный заказ с неположительной суммой
  не обрабатывается (защита в глубину).
- **Сбои IP-лимита наблюдаемы** - ошибка БД при проверке IP-лимита по-прежнему
  fail-open, но теперь логируется (с троттлингом), а не отключает энфорсмент молча.

### Надёжность и фиксы (из ревью)

- **Корректный график трафика** - график статистики клиента суммировал бакеты
  no-op-редьюсером и показывал только первый сэмпл; теперь суммирует правильно.
- **Безопаснее миграция 1.3** - миграция anytls / domain-strategy выполняется в
  транзакции и проверяет каждую запись (раньше игнорировала ошибки сохранения и несла
  мёртвый фильтр, грузивший все строки).
- **IDN-домены панели работают** - Unicode-домен (напр. `панель.рф`) совпадает с
  punycode-`Host` от браузера вместо отказа `403`.
- **Ограниченный public-IP-пробинг** - запрос публичного IP в `s-ui uri` ограничивает
  тело ответа (1 МиБ), как и все прочие исходящие читатели.
- **Без дёрганья drawer** - `isMobile` снова чистый computed; дефолт открытия drawer
  следует за брейкпоинтом через watcher.
- **Понятный лог старта ядра** - падение запуска sing-box-ядра логируется явно (панель
  намеренно остаётся поднятой, чтобы починить конфиг из UI).

### Производительность и чистка (из ревью)

- **Индекс истории заказов** - `payment_orders.telegram_user_id` индексирован, история
  заказов / возвратов больше не сканирует всю таблицу.
- **Легче установка фронтенда** - удалены три неиспользуемые зависимости (`core-js`,

**Сохранено**
- Разовый импорт из **загрузки локального `.db`** - UI-визард, API и
  `import-xui --src` - с dry-run, стратегией конфликтов, plan/apply и откатом.

Ручная миграция не нужна - устаревшие таблицы 3x-ui удаляются на старте.

## [1.5.7-beta6] - 2026-06-05 - усиление безопасности и надёжности, производительность и доступность

Релиз-усиление по итогам полного аудита качества кода, оптимизации и
безопасности панели. Новых функций нет и **ручная миграция не требуется** - он
закрывает несколько брешей в безопасности, убирает риски тихих отказов и паник,
урезает фронтенд-бандл на ~60% и чинит несколько багов целостности данных. Два
пункта меняют существующее поведение - см. **Ломающие изменения**.

### Безопасность

- **Обновление до Go 1.26.4** - закрывает две достижимые уязвимости стандартной
  библиотеки Go (`GO-2026-5037` в `crypto/x509`, `GO-2026-5039` в `net/textproto`).
- **Scope API-токенов теперь энфорсится.** Раньше action-эндпоинты `apiv2`
  выполняли любое действие независимо от scope токена, так что токен
  `read`/`observability`/`telegram`/`database` мог писать конфиг, перезапускать
  панель и читать настройки. Теперь каждое действие гейтится: запись и перезапуск
  требуют `write`/`admin`, чтение конфига/учёток - `read`/`write`/`admin`, метрики
  допускают ещё и `observability`. Доступ через браузерную сессию админа не
  изменился. *(Ломающее.)*
- **Удалённый импорт/синк x-ui усилен против SSRF.** Удалённые импорты валидируют
  целевой URL и **повторно проверяют разрешённый IP в момент соединения** (защита
  от DNS-rebinding), с ограничением редиректов; cloud-metadata, loopback и
  приватные диапазоны блокируются для недоверенных (scoped-токен) вызовов.
  **Источники `file` и `ssh` теперь доступны только админу**, а плановый синк
  выполняет `file`/`ssh`-источник только из профиля, сохранённого админом.
  *(Ломающее.)*
- **Секреты at-rest.** При заданном `SUI_SECRETBOX_KEY` сохранённые секреты теперь
  **одноразово ре-шифруются на старте** под этим внедатабазным ключом - значение,
  записанное до включения ключа, больше не восстановить из одной только БД.
  Шифрование учёток удалённых панелей выводит ключ из случайного per-install
  секрета вместо предсказуемого дефолта.
- **Брутфорс логина.** Добавлен throttle **по имени пользователя** поверх лимита
  по IP, чтобы распределённая атака на один аккаунт тоже тормозилась.
- **Session fixation.** ID сессии теперь **ротируется при логине** - подкинутая
  pre-auth cookie не переживает аутентификацию.
- **Транспорт и заголовки.** HSTS доверяет `X-Forwarded-Proto` только от доверенного
  прокси; CSRF-cookie соблюдает строгий `SameSite`; `s-ui admin -reset` генерирует
  случайный пароль вместо фиксированного дефолта.
- **Telegram-платежи** сверяют Telegram-id плательщика; proxy-URL со встроенными
  кредами маскируются в логах.

### Надёжность и фиксы

- **Нет ложного «running» ядра.** Если сгенерированный конфиг sing-box не
  парсится, ядро теперь возвращает ошибку, а не запускает тихо пустой инстанс,
  рапортуя «здоров», пока ничто не слушает.
- **Фоновые джобы не роняют панель.** Cron-джобы изолированы от паник и
  skip-if-still-running; джоба WAL-checkpoint защищена от nil-разыменования на
  старте.
- **Устойчивее генерация подписок.** Малформный конфиг inbound/клиента больше не
  роняет генераторы link/Clash/JSON-подписок - плохое поле пропускается.
- **Лента изменений остаётся доступной.** Имя клиента с кавычкой или другим
  JSON-метасимволом больше не портит сохранённый журнал изменений - раньше из-за
  этого админская страница **Changes** отдавала пустой ответ всем.
- **Корректные ссылки при bulk-правке.** Правка группы клиентов с *разными*
  наборами Inbounds теперь пересобирает ссылки каждого клиента из его
  собственных Inbounds, а не копирует набор первого.
- **Единообразные ошибки API** с документированным success-конвертом и
  отредактированными внутренними деталями.

### Производительность

- **Бэкенд.** IP-монитор пишет накопленные записи одним батч-upsert'ом (вместо
  запроса на каждый IP); горячий путь подписки кэширует display-настройки (≈8
  запросов меньше на запрос), а чтения `settings` теперь идут по индексу.
- **Фронтенд-бандл 6.2 МБ → 2.5 МБ (-60%).** `moment` и date-picker грузятся
  лениво вместе со своими страницами, иконки переехали с полного веб-шрифта
  Material Design (~2.9 МБ) на инлайн-SVG-пути.

### Доступность

- Иконочные кнопки действий админа (редактировать / изменения / удалить) получили
  доступные имена для скринридеров.

### Ломающие изменения

- **Scoped-токены теряют доступ, которого у них не должно было быть.** Интеграция,
  где токен `read`/`observability`/`telegram`/`database` писал конфиг,
  перезапускал панель или читал настройки (что работало лишь из-за бреши выше),
  теперь отклоняется - используйте токен `admin` или подходящий `write`.
- **`file`/`ssh`-профили синка x-ui должны быть сохранены админом.** После
  апгрейда плановый профиль синка с локальным `file`/`ssh`-источником не запустится,
  пока **админ не пере-сохранит его** (панель больше не может доказать, что
  до-апгрейдный профиль создан админом). Пере-сохранение из админ-сессии его
  восстанавливает.

### Обновление

Ручной миграции и правки конфига не нужно. Таблица `settings` получает уникальный
индекс автоматически при первом старте; при использовании `SUI_SECRETBOX_KEY`
одноразовый ре-seal секретов выполняется на старте. Просмотрите два **Ломающих
изменения**, если используете scoped API-токены или `file`/`ssh` плановый синк.
Релиз-ноуты: [`docs/releases/v1.5.7-beta6.md`](docs/releases/v1.5.7-beta6.md).

## [1.5.6-beta8] - 2026-06-03 - миграция 3x-ui: Outbounds, матчеры маршрутизации, TLS-сертификаты и DNS

- Proxy Outbounds теперь мигрируют как Outbounds в s-ui: раньше обрабатывались
  только WARP (WireGuard), `freedom` и `blackhole`, поэтому запись `outbounds`
  Xray типа `vmess`/`vless`/`trojan`/`shadowsocks`/`socks`/`http` молча
  отбрасывалась, и цепочечный/proxy Outbound пропадал из перенесённой панели.
  Теперь каждый превращается в полноценный Outbound sing-box (сервер/порт,
  `uuid`/`password`/`method`/логин-пароль, `flow` для VLESS, блок TLS/Reality и
  транспорт `ws`/`grpc`/`http`/`httpupgrade`) и регистрируется как цель
  маршрутизации, поэтому ссылавшееся на него правило резолвится в перенесённый
  Outbound вместо «требует ручной проверки».
- Системные Outbounds сопоставляются со своим аналогом в sing-box:
  `freedom`→`direct`, `blackhole`→`block`, а Outbound `dns` превращается в
  действие маршрута `hijack-dns` (в sing-box нет Outbound `dns`). `loopback` и
  любой протокол, которого нет в Xray (например, `hysteria`), выводятся как
  предупреждение для ручного пересоздания, а не отбрасываются молча.
- Никакой тихой потери при выключенном импорте роутинга: прокси/WARP Outbounds
  лежат в исходном `xrayConfig`, который читается только при импорте роутинга.
  Если импорт роутинга выключен, но в источнике есть Outbounds, план теперь
  предупреждает, что они не перенесены и как их перенести.
- Outbounds создаются только если они новые (повторный импорт или
  запланированная синхронизация не затирают отредактированный оператором
  Outbound с тем же тегом), а в отчёте об импорте появляется счётчик `outbounds`
  (импортировано/пропущено).
- Миграция маршрутизации и DNS теперь применяется к живому конфигу: они
  мерджатся в активную настройку `config` sing-box (route-правила/rule-set,
  DNS-серверы/правила) с сохранением существующих правил и дедупликацией
  rule-set/серверов по тегу. Раньше импорт писал их в отдельную настройку,
  которую панель не загружала, поэтому импортированная маршрутизация не
  действовала - теперь действует.
- Правила маршрутизации покрывают гораздо больше матчеров вместо «ручной
  проверки»: `port`/`sourcePort` (включая диапазоны), `network`, `protocol`,
  `source`, `inboundTag` (→`inbound`), `user` (→`auth_user`) и не-`geosite`
  домены (`domain:`/`full:`/`keyword:`/`regexp:`/без префикса → `domain_suffix`/
  `domain`/`domain_keyword`/`domain_regex`). Матчеры `geosite:`/`geoip:`
  становятся remote `rule_set` (MetaCubeX `meta-rules-dat`), так как sing-box
  1.12 удалил инлайновые поля `geoip`/`geosite`; для source `geoip` ставится
  `rule_set_ip_cidr_match_source`. `attrs` и `balancerTag` по-прежнему требуют
  ручной проверки - в sing-box нет аналога.
- Блок `dns` из Xray переводится в формат sing-box (типизированные серверы
  `udp`/`tls`/`https`/`h3`/`quic`/`tcp`/`local`, серверы с привязкой к доменам
  становятся dns-правилами, плюс `final`, стратегия запросов и `client_subnet`)
  вместо копирования «как есть», которое давало невалидный блок. `hosts`/`fakedns`
  отмечаются для ручной настройки.
- Не-reality TLS-сертификаты теперь мигрируют: Inbound, у которого в
  `tlsSettings` лежит inline-сертификат/ключ, получает настоящую TLS-запись s-ui
  (серверный сертификат + клиентский блок); сертификат, заданный только путём к
  файлу, отмечается для ручной загрузки, так как импортёр читает лишь базу, а не
  диск исходного хоста.
- WebSocket-транспорт переносит все заголовки запроса, не только `Host`.
- Доп. для Outbounds: `packet_encoding` (`xudp`) выставляется, если источник
  его использовал; Outbound с несколькими серверами превращается в членов
  по-серверно плюс группу `urltest`; Xray `mux` сообщается, а не включается - мультиплекс sing-box несовместим по протоколу с Xray mux, и его включение
  сломало бы Outbound.
- Веб-админка сохраняет несохранённые правки при фоновом обновлении: страницы
  Basics, DNS и Routing привязывали формы к живому конфигу из стора, поэтому
  10-секундный опрос конфига (и события перезагрузки по WS) молча откатывали
  правки в процессе - теперь они редактируют локальную копию, которая держится
  до сохранения.
- Импорт маршрутизации больше не создаёт конфиг, который отвергает sing-box:
  Xray-ссылка на внешний geoip (`ext:<файл>:<код>`, напр. `ext:geoip_RU.dat:ru`)
  и «голые» IP попадали в `ip_cidr` как есть, что sing-box не может распарсить
  (`ipcidr: parse: no '/'`), и ядро не стартовало. Теперь `ext:` маппится в
  geoip rule_set, голым IP добавляется маска, а непарсящееся значение
  отбрасывается с предупреждением, а не ломает весь конфиг.
- Мигрированный DNS больше не мешает ядру стартовать: DNS-сервер, заданный
  доменом (`https://dns.google/...`, `tls://...`), выдавался без `domain_resolver`,
  что sing-box 1.13 отвергает (`missing domain resolver for domain server
  address`). Теперь каждому доменному серверу ставится `domain_resolver` -
  IP-адресный сервер из миграции или добавленный local-bootstrap - так же, как
  это делает встроенный DNS-редактор s-ui; TLS/HTTP-серверам добавляются блоки
  `tls`/`headers`, чтобы мигрированный сервер был идентичен созданному вручную.
- Trojan Inbound больше не роняет ядро: редактор Inbound писал верхнеуровневый
  `password`, который sing-box у Trojan Inbound отвергает (`unknown field
  "password"` - аутентификация идёт по `users`, по клиентам). Поле пароля теперь
  только для Outbounds, а оставшийся верхнеуровневый `password` срезается при
  сборке конфига (так что уже созданные Inbounds чинятся без правки).
- Полные примечания к релизу: [`docs/releases/v1.5.6-beta8.md`](docs/releases/v1.5.6-beta8.md).

## [1.5.5-beta4] - 2026-05-26 - отчёт об устранении проблем и технического долга

### 1. Безопасность, аутентификация и аудит

- **Принудительный сброс пароля при импорте.**
  Суть проблемы: интерфейс предлагал режим `reset_required` при миграции
  администраторов из x-ui, но backend не имел отдельного durable-состояния для
  обязательной смены пароля.
  Влияние: в модель пользователя добавлено состояние `force_password_reset`,
  API-контракт синхронизирован с интерфейсом, а временный пароль больше не
  генерируется и не попадает в отчёт импорта для этого режима.
- **Защита токенов от атак и устаревания.**
  Суть проблемы: WebSocket-токены проверялись с измеримой разницей во времени,
  устаревший заголовок авторизации `Token` не имел жёсткой даты отключения, а
  миграция legacy API-токенов могла включить ранее отключённые токены.
  Влияние: потребление WebSocket-токенов переведено на безопасный
  match-and-delete путь, legacy `Token` header получает отказ после Sunset, а
  миграция старых токенов сохраняет исходный enabled/disabled статус.
- **Защита от утечек системных данных.**
  Суть проблемы: system info мог раскрывать private и link-local IP-адреса,
  секреты Telegram backup требовали более явного владения памятью, а generated
  admin passwords в MigrateXui были слишком легко видимы на экране.
  Влияние: внутренние IP фильтруются из ответа, payload и passphrase Telegram
  backup зануляются после использования, а generated admin passwords скрыты до
  явного reveal и автоматически очищаются.
- **Приоритезация и качество аудита.**
  Суть проблемы: при переполнении audit queue важные warn/security события
  могли вытесняться обычными `info`, успешная legacy-расшифровка создавала
  лишний noise, ошибки сохранения статистики не оставляли полноценного следа,
  а URL-настройки принимали управляющие символы.
  Влияние: audit writer сохраняет приоритет warning/security событий, лишний
  secretbox fallback noise убран, failures при commit статистики фиксируются в
  audit, а optional URL settings отклоняют control characters и небезопасные
  формы ввода.

### 2. Импорт, синхронизация X-UI и интерфейс

- **Точное следование настройкам пользователя.**
  Суть проблемы: фоновая cron-синхронизация с X-UI использовала жёстко заданные
  правила и могла игнорировать пользовательские поля профиля: `OnlyNew`, импорт
  настроек, истории, routing и режим обработки администраторов.
  Влияние: scheduler backend передаёт сохранённую import policy в планирование
  и применение импорта, поэтому cron sync исполняет настройки администратора.
- **Работа с крупными импортами.**
  Суть проблемы: JSON-план миграции читался как обычное multipart-поле с
  лимитом 8 MiB, из-за чего крупные панели нельзя было применить тем же
  контрактом; оборванные загрузки могли оставлять временные директории.
  Влияние: multipart-поле `plan` читается потоково из временного хранилища под
  общим лимитом запроса 200 MiB, а старые `xui-import-*` temp directories
  очищаются автоматически по безопасному возрастному правилу.
- **Изоляция и точность импорта.**
  Суть проблемы: ошибка удаления старых TLS-записей в replace-сценарии могла
  быть проигнорирована перед созданием новых записей, а пропущенные WireGuard
  endpoints попадали в счётчик skipped inbounds.
  Влияние: ошибки удаления TLS прерывают транзакцию и приводят к безопасному
  rollback, а отчёт импорта получил корректный отдельный счётчик skipped
  endpoints.
- **UX восстановления и откатов.**
  Суть проблемы: ошибки apply могли возвращать пользователя на прошлый шаг без
  понятного объяснения, rollback ждал фиксированную секунду перед reload, а
  другие активные сессии не получали realtime-сигнал об изменении конфигурации.
  Влияние: MigrateXui показывает apply error inline, rollback ждёт
  health-check перед reload, а backend публикует `config_invalidated` после
  успешного rollback.

### 3. База данных, резервное копирование и отказоустойчивость

- **Защита backup и процесса миграции БД.**
  Суть проблемы: SIGHUP timeout был жёстко зафиксирован на 3 секундах, WAL
  checkpoint мог фатально сорвать backup на заблокированной SQLite DB,
  отсутствие `settings.config` блокировало versioned restore, а ошибки
  post-migration adapt при запуске оставались warning-only.
  Влияние: timeout вынесен в env-настройку, WAL checkpoint получил fallback
  `TRUNCATE -> FULL`, backup без `settings.config` восстанавливается с
  предупреждением, а повреждённый post-migration adapt останавливает startup.
- **Масштабируемость БД и гонки при старте.**
  Суть проблемы: SQLite pool имел фиксированные лимиты, а параллельный
  first-start мог создать дубликаты настроек по умолчанию.
  Влияние: добавлены env-переменные для настройки SQLite pool, а default
  settings создаются через DB-level idempotent insert path.
- **Отказоустойчивость IP-монитора.**
  Суть проблемы: transient DB read error в IP-monitor path мог привести к
  пропуску неизвестного адреса в enforce-mode.
  Влияние: при ошибке чтения `client_ips` cache entry считается недостоверным,
  и enforcement переходит в fail-closed поведение.

### 4. Сеть, гонки данных и стабильность ядра

- **Защита от OOM и самовосстановление realtime.**
  Суть проблемы: import-xui rate-limit state мог расти без верхней границы при
  потоке запросов с уникальных IP, а после сетевого сбоя frontend мог навсегда
  остаться в degraded polling mode.
  Влияние: rate-limit cache получил bounded eviction и очистку expired buckets,
  а WebSocket runtime выполняет healing reconnect attempts из fallback-режима.
- **Устранение data races.**
  Суть проблемы: конкурентный доступ к таймерам перезапуска ядра, Telegram HTTP
  client и token-use flush мог приводить к race detector failures, паникам или
  записи через устаревший DB handle.
  Влияние: критичные участки защищены mutex/single-flight/barrier механизмами,
  а token-use flush lifecycle синхронизирован с DB reset и API test lifecycle.
- **Умные повторы и защита от штормов.**
  Суть проблемы: cron sync использовал слишком короткие fixed retries,
  token-use write failures не имели backoff circuit, update-check ходил на
  GitHub без ETag, причины ошибок sync терялись, а WARP auth headers были
  хрупко распределены по коду.
  Влияние: retry-политики получили exponential backoff, token-use flush получил
  circuit breaker, release checks используют `If-None-Match`, sync-fail
  summaries включают sanitized error class/detail, а WARP authorized headers
  централизованы.
- **Работа с IPv6 и единый API route registry.**
  Суть проблемы: system info path мог паниковать на коротких interface
  flags/address данных, включая нестандартные IPv6-only окружения, а import-xui
  routes расходились между v1 и v2 API.
  Влияние: сетевые интерфейсы проверяются по содержимому и длине данных, а
  import-xui endpoints регистрируются из общего route spec для `/api` и
  `/apiv2`.

## [1.5.2-beta-hotfix2] - 2026-05-18 - снятие legacy unique-индекса client_ips

## Гайд по обновлению (русский)

Обновление можно делать прямо поверх, без потери данных и без полной
перенастройки. При старте панели автоматически выполняется
`cmd/migration` → `database.AdaptToCurrentVersion`: схема БД
подтягивается до актуальной версии, добавляются недостающие индексы,
все ваши настройки, inbounds/outbounds/клиенты/tls/сервисы и
API-токены остаются на месте, а пароль админа в открытом виде
автоматически перешьётся в bcrypt при первом успешном логине. Бэкапы,
сделанные на старых версиях S-UI (1.0/1.1/1.2/1.3), можно восстановить
напрямую через панель - миграция применяется к загруженному бэкапу в
том же потоке.

1. Сделайте бэкап на всякий случай:
   - через панель: **Backup → Backup**, сохраните файл `s-ui_*.db`;
   - либо скопируйте файл вручную: `cp /usr/local/s-ui/db/s-ui.db /root/s-ui.db.bak`.
2. Остановите сервис: `systemctl stop s-ui`.
3. Замените бинарник или docker-образ на новую сборку:
   - вручную: распакуйте свежий архив в `/usr/local/s-ui/`;
   - docker: поменяйте тег образа на `ghcr.io/deposist/s-ui-x`
     и выполните `docker compose pull && docker compose up -d`.
4. Запустите сервис: `systemctl start s-ui`.
5. Зайдите в панель так же, как раньше. Пароль будет автоматически
   заменён на bcrypt-хеш после первого успешного логина - никаких
   ручных действий не нужно.

После апгрейда стоит проверить:

- Если панель работает за reverse-proxy и вам важно видеть реальный IP
  клиента в логах входа, выставьте переменную окружения
  `SUI_TRUSTED_PROXIES` со списком CIDR ваших прокси (например
  `127.0.0.1/32,10.0.0.0/8`). Без этой переменной заголовок
  `X-Forwarded-For` игнорируется и в журналах будет адрес прокси.
- Если внешние подписки берутся с локального адреса
  (`http://127.0.0.1:.../sub`), выставьте `SUI_ALLOW_PRIVATE_SUB_URLS=true`.
- Если вы устанавливали панель старым скриптом (`deposist/s-ui`),
  один раз обновите его на новый репозиторий:
  `wget -O /usr/bin/s-ui https://raw.githubusercontent.com/deposist/s-ui-x/main/s-ui.sh && chmod +x /usr/bin/s-ui`.
- Лимит входа - 5 неуспешных попыток с одного IP за 15 минут блокируют
  IP на 15 минут. Если вы вводили пароль с ошибками много раз, подождите
  блок-окно или перезапустите сервис, чтобы счётчик сбросился.

## Откат

Если что-то пошло не так, достаточно восстановить бэкап:

1. `systemctl stop s-ui`.
2. `cp /root/s-ui.db.bak /usr/local/s-ui/db/s-ui.db`.
3. Восстановите предыдущий бинарь или верните `docker compose` на
   предыдущий тег образа.
4. `systemctl start s-ui`.

Префикс bcrypt в колонке `users.password` совместим с предыдущим бинарём
в том смысле, что старый бинарь просто не сматчит хешированный пароль -
в этом случае `s-ui admin -reset` восстанавливает известные креденшелы.
Данные в безопасности; на откате может потребоваться только CLI-сброс
пароля админа.
