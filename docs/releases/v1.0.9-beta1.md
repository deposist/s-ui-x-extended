# S-UI-X Extended v1.0.9-beta1

Version 1.0.9-beta1 fixes updates from the beta channel to a stable release and removes a flaky external keyserver dependency from release builds. It does not change the database schema or runtime configuration.

## Fixed

- When the beta channel selects a newer stable release, the updater now validates the archive against that release's `main` manifest. Previously it compared the stable manifest with the saved `beta` channel and stopped with `update manifest is invalid`.
- Prerelease artifacts still require a beta manifest. The updater continues to bind the version, platform, archive name, and SHA-256 digest before replacing the installed binary.
- Cronet release builds install an official pinned Debian archive keyring package after verifying its SHA-256 digest. They no longer fetch individual keys from `keyserver.ubuntu.com`, which could return an incomplete set during parallel release jobs.
- Release regression checks verify the pinned package URL and digest, the extraction command, and the absence of the old public-keyserver script.

## Upgrade

Beta10 and beta11 users can install this release from the console:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.0.9-beta1/install.sh \
  | sudo bash -s -- v1.0.9-beta1
```

If you are already logged in as `root`:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.0.9-beta1/install.sh) \
  v1.0.9-beta1
```

After installation, check the version and service:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

The first command must report `1.0.9-beta1`, and `systemctl` must print `active`. The installer preserves `/usr/local/s-ui/db` and `/etc/s-ui`.

This is a beta release. Test it on a non-critical server before using it in production.

# S-UI-X Extended v1.0.9-beta1

Версия 1.0.9-beta1 исправляет обновление с beta-канала до стабильного релиза и убирает ненадёжную зависимость релизной сборки от публичного сервера ключей. Схема базы и рабочая конфигурация не меняются.

## Исправления

- Когда beta-канал выбирает более новый стабильный релиз, модуль обновления проверяет архив по манифесту `main` этого релиза. Раньше он сравнивал стабильный манифест с сохранённым каналом `beta` и останавливался с ошибкой `update manifest is invalid`.
- Для предварительного релиза по-прежнему нужен манифест beta. Перед заменой исполняемого файла проверяются версия, платформа, имя архива и SHA-256.
- Релизная сборка Cronet устанавливает официальный закреплённый пакет ключей Debian после проверки SHA-256. Она больше не загружает отдельные ключи с `keyserver.ubuntu.com`, который мог вернуть неполный набор при параллельной сборке.
- Регрессионные проверки сверяют адрес и SHA-256 пакета, команду распаковки и отсутствие старого скрипта для публичного сервера ключей.

## Обновление

Пользователи beta10 и beta11 могут установить этот релиз из консоли:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.0.9-beta1/install.sh \
  | sudo bash -s -- v1.0.9-beta1
```

Если вы уже вошли как `root`:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.0.9-beta1/install.sh) \
  v1.0.9-beta1
```

После установки проверьте версию и службу:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

Первая команда должна показать `1.0.9-beta1`, команда `systemctl` - `active`. Установщик сохраняет `/usr/local/s-ui/db` и `/etc/s-ui`.

Это бета-версия. Сначала проверьте её на некритичном сервере.
