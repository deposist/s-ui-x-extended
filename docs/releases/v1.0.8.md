# S-UI-X Extended v1.0.8

Version 1.0.8 contains the work released in the 1.0.8 beta series after version 1.0.7. It strengthens update and recovery paths, adds managed local rule-sets and nested rules, improves payment recovery and database durability, updates the bundled core, and fixes panel and release edge cases.

## Security and self-update

- Self-update validates HTTPS release metadata, the requested version and channel, platform, archive name, SHA-256 digest, download limits, and archive contents before it replaces the installed binary.
- Every installable Linux archive has an adjacent checksum and metadata manifest. Releases without the required files are not offered by the panel.
- Failed downloads and extraction remove partial files. Archive validation rejects oversized members, unsafe paths, links, unexpected inventory, and trailing data.
- Update application is serialized across processes. A durable marker binds the candidate, backup, and database snapshot to one transaction so an interrupted update cannot overwrite valid rollback state.
- Startup migrates the numeric `.update-pending` marker written by beta8 to the current format and verifies the installed and backup binaries by SHA-256. Malformed recovery state still stops startup.
- Compact `betaN` and `rcN` suffixes are compared numerically. This fixes the beta10 behavior that treated beta9 as newer than beta10 and beta11.
- Telegram API responses are size-limited. Direct rule-set downloads allow HTTPS only and block private or infrastructure addresses at connection time, including redirects and DNS rebinding.
- Updated affected Go, QUIC, Axios, gRPC, text-processing, and frontend build dependencies.

## Database, payments, and recovery

- Database restore drains active panel, subscription, and cron work before replacing the SQLite handle. The rollback route no longer waits on its own request lease.
- Selective backup uses one database snapshot and checks SQLite integrity, foreign keys, and the TLS sentinel before returning an export.
- Traffic, IP-monitor, token-use, and audit batches keep uncommitted data and retry after a database write fails.
- Scheduled jobs stop with a bounded wait. Application startup closes components that were already initialized if a later startup step fails.
- Paid subscriptions store every provider charge in a durable ledger. Telegram offsets, CryptoBot cursors, and reconciliation cursors advance only after the related work is saved.
- Confirmed payments can complete after the pending deadline. Missing CryptoBot invoices remain recoverable, and one failed invoice does not stop the rest of a cancellation batch.
- Refunds restore the capacity bought by the order without rewriting current usage or lifetime traffic counters. Repeated refunds and AWG suspend or resume failures are reported accurately.
- An x-ui import that commits successfully but cannot checkpoint is reported as a warning rather than a failed import.

## Managed rule-sets and routing

- Regional presets download `.srs` files before saving the configuration, verify them, and use local paths. Core startup no longer depends on GitHub availability.
- One rule-set file is limited to 32 MiB and one materialization batch to 64 MiB. Assets and `rulesets/sources.json` are replaced together, so a failed batch leaves the last working files in place.
- A daily job refreshes the recorded sources. An authenticated, CSRF-protected endpoint can download directly or through the outbound selected in the preset drawer.
- Doctor checks and save-time validation reject missing, non-regular, oversized, truncated, or otherwise invalid local rule-set files.
- The Russia preset uses `geosite-category-ru.srs` from the maintained runetfreedom collection instead of the removed SagerNet path.
- Route and DNS editors support nested `and` and `or` groups. Validation reports the exact invalid descendant and limits each request to 1 MiB, 64 levels, and 4,096 nodes.
- Saving preserves supported route and DNS action fields, including direct dialer options, `override_gateway`, `disable_cache`, `rewrite_ttl`, and `client_subnet`.

## Panel, API, and realtime behavior

- List pages distinguish an empty collection from filtered results and show the relevant setup action. Drawers explain which missing field or selection disables Save.
- Login and Settings adapt to narrow viewports. Settings tracks unsaved changes, explains units and zero values, and separates Save from Restart.
- The Nexus shell provides accessible logout controls, remembers the desktop sidebar state, and announces server status through a live region. Dense overview values resize or scroll instead of being clipped.
- WebSocket recovery switches to degraded polling after an offline token request and retries when connectivity returns. Connection generations prevent stale sockets from reconnecting after logout or clearing newer state.
- CSRF refresh uses one active request and retries one failure. Data loading, fallback polling, and update polling no longer overlap or let an older failure replace a newer result.
- Damaged saved JSON and blocked browser storage no longer stop affected views. API payload handling preserves valid `false`, `0`, and empty-string values.
- Share-link and Clash parsers reject missing credentials, malformed hosts or ports, invalid JSON or YAML shapes, and out-of-range ECH data instead of panicking or changing the input silently.
- Generated links escape query values and format IPv6 addresses correctly. Protocol state no longer leaks from one generated address to another.
- Sessions follow the current database handle. Realtime registration and delivery are synchronized, HTTPS redirects preserve the configured TLS port, iframe headers follow SameSite settings, and immutable caching applies only to hashed assets.
- Initial admin credentials are consumed only after a successful password change. Cross-site session cookies are supported when explicitly configured.

## Core and certificates

- The bundled core is `sing-box-extended v1.13.14-extended-2.5.4`.
- WireGuard endpoint IPC exposes the peer state used by AmneziaWG provisioning. Core lifecycle and endpoint IPC share synchronization so an endpoint cannot close during a request.
- Core startup rolls back partial initialization. Concurrent shutdown runs once and returns the stored result.
- Clash log observers receive entries again. Panic and fatal levels keep their terminal behavior after the entry is written.
- Rule-set readers close files and zlib streams, reject truncated data, bad checksums, and bytes after the declared rules.
- Certificate renewal retries a certificate pair that was saved but not applied. Certificate and private-key files are published as one complete generation.
- Telegram backup validates its fixed Argon2 parameters before deriving a key and carries cancellation through snapshot creation, encryption, and upload.
- Provider definitions accept custom HTTP headers, and group `providers` accepts one value or a list.
- REALITY advertises client version `26.7.11`. Servers that still cap `maxClientVer` at `1.8.1` need that bound updated.

## Release and deployment

- Release workflows validate the requested tag, its source commit, release state, archive metadata, and checksums before publication. A published tag cannot be reused with different assets.
- Linux and Windows packages are built from the exact tag. The workflow verifies archive inventories and runtime architectures, scans release files, publishes SPDX SBOMs, and attaches provenance.
- Docker publication verifies each architecture and runs the final smoke check by immutable platform manifest digest.
- The default Compose image and frontend package version are `1.0.8`.

## Upgrade

The installer preserves the panel database and configuration. Normal startup creates the provider-charge ledger; no manual configuration change is required.

Run on Linux:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.0.8/install.sh \
  | sudo bash -s -- v1.0.8
```

If you are already logged in as `root`:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.0.8/install.sh) \
  v1.0.8
```

Check the installed version and service state:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

The first command must report `1.0.8`, and `systemctl` must print `active`.

Servers caught in the beta8 to beta9 restart loop cannot use the panel updater. Run the console command above. Do not delete `/usr/local/s-ui/db` or `/etc/s-ui` during recovery.

Beta10 and beta11 cannot finish a panel update to stable 1.0.8 while the saved update channel is `beta`: the stable archive correctly carries a `main` manifest, but those builds compare it with the selected channel and report `update manifest is invalid`. Switch the update selector to **Main (stable)** before checking and applying 1.0.8, or use the console command above. If beta10 offers beta9, do not apply that downgrade.

# S-UI-X Extended v1.0.8

Версия 1.0.8 включает изменения всей линейки beta после 1.0.7. В ней усилены обновление и восстановление, добавлены локальные наборы правил и вложенные условия, исправлены платежи и работа с базой, обновлён core, устранены ошибки панели и публикации релизов.

## Безопасность и самообновление

- Перед заменой исполняемого файла модуль обновления проверяет HTTPS-метаданные, версию и канал, платформу, имя архива, SHA-256, размер загрузки и содержимое архива.
- Рядом с каждым Linux-архивом публикуются контрольная сумма и файл метаданных. Панель не предлагает релиз без этих файлов.
- После ошибки загрузки или распаковки временные файлы удаляются. Проверка архива отклоняет слишком большие элементы, опасные пути, ссылки, лишние файлы и данные после конца архива.
- Обновления выполняются последовательно даже между процессами. Файл состояния связывает новый исполняемый файл, резервную копию и снимок базы с одной транзакцией, поэтому прерванная операция не затирает рабочее состояние отката.
- При запуске панель переводит числовой `.update-pending` от beta8 в текущий формат и проверяет установленный и резервный исполняемые файлы по SHA-256. Повреждённое состояние восстановления останавливает запуск.
- Компактные суффиксы `betaN` и `rcN` сравниваются по номеру. Это исправляет поведение beta10, которая считала beta9 новее beta10 и beta11.
- Ответы Telegram API ограничены по размеру. Прямая загрузка наборов правил принимает только HTTPS и блокирует закрытые и служебные адреса при подключении, в том числе после перенаправления и при подмене DNS.
- Обновлены затронутые зависимости Go, QUIC, Axios, gRPC, обработки текста и сборки frontend.

## База данных, платежи и восстановление

- Перед заменой SQLite восстановление ждёт завершения активных запросов панели, подписок и фоновых заданий. Маршрут отката больше не ждёт завершения собственного запроса.
- Выборочный экспорт использует один снимок базы и проверяет целостность SQLite, внешние ключи и TLS-маркер.
- Счётчики трафика, IP-мониторинг, использование токенов и аудит сохраняют незаписанные данные после ошибки базы и повторяют запись.
- Фоновые задания завершаются с ограниченным ожиданием. Если поздний этап запуска завершается ошибкой, приложение закрывает уже запущенные компоненты.
- Платные подписки хранят каждое списание провайдера. Смещения Telegram, курсоры CryptoBot и сверки сдвигаются только после сохранения связанной операции.
- Подтверждённый платёж может завершить заказ после истечения срока ожидания. Пропавшие счета CryptoBot остаются доступными для восстановления, а ошибка одного счёта не останавливает обработку остальных.
- Возврат восстанавливает купленный лимит и не переписывает текущий или накопленный трафик. Повторные возвраты и ошибки остановки или запуска AWG отображаются корректно.
- Если импорт x-ui завершил транзакцию, но не смог выполнить checkpoint, панель сообщает предупреждение вместо ложного сообщения о провале всего импорта.

## Локальные наборы правил и маршрутизация

- Региональные шаблоны загружают `.srs` до сохранения конфигурации, проверяют файлы и используют локальные пути. Запуск core больше не зависит от доступности GitHub.
- Размер одного файла ограничен 32 МиБ, одной загрузки - 64 МиБ. Файлы и `rulesets/sources.json` заменяются вместе, поэтому после ошибки остаётся последний рабочий набор.
- Ежедневное задание обновляет записанные источники. Защищённый авторизацией и CSRF маршрут умеет загружать напрямую или через outbound, выбранный в настройках шаблона.
- Диагностика и проверка при сохранении отклоняют отсутствующие, необычные, слишком большие, обрезанные и повреждённые файлы.
- Российский шаблон использует `geosite-category-ru.srs` из поддерживаемого набора runetfreedom вместо удалённого пути SagerNet.
- Редакторы маршрутов и DNS поддерживают вложенные группы `and` и `or`. Ошибка указывает точное место, а запрос ограничен 1 МиБ, 64 уровнями и 4096 узлами.
- При сохранении остаются поддерживаемые параметры маршрутов и действий DNS, в том числе dialer для direct, `override_gateway`, `disable_cache`, `rewrite_ttl` и `client_subnet`.

## Панель, API и события

- Списки отличают пустой раздел от поиска без совпадений и предлагают подходящее действие. Формы объясняют, какое поле или выбор блокирует сохранение.
- Экран входа и настройки адаптированы для узких экранов. Настройки отслеживают несохранённые изменения, поясняют единицы и нулевые значения, визуально разделяют сохранение и перезапуск.
- В Nexus доступны кнопки выхода для клавиатуры, сохраняется состояние боковой панели, статус сервера объявляется через live region. Плотные показатели уменьшаются или прокручиваются вместо обрезания.
- После ошибки получения токена без сети WebSocket переходит на резервный опрос и повторяет подключение при восстановлении сети. Поколения соединений не дают старому сокету подключиться после выхода или затереть новое состояние.
- Обновление CSRF использует один активный запрос и один повтор после ошибки. Загрузка данных и опрос больше не пересекаются, старая ошибка не заменяет новый успешный результат.
- Повреждённый JSON и заблокированное хранилище браузера не ломают связанные экраны. API сохраняет допустимые значения `false`, `0` и пустую строку.
- Разбор ссылок и Clash-конфигураций отклоняет отсутствующие данные доступа, неверные адреса и порты, ошибочную структуру JSON или YAML и недопустимые ECH-поля. Паника и скрытая правка входных данных устранены.
- Ссылки экранируют параметры и правильно оформляют IPv6. Состояние одного протокола не попадает в следующий адрес.
- Сессии используют актуальное подключение к базе. Регистрация и доставка событий синхронизированы, HTTPS-переходы сохраняют настроенный TLS-порт, iframe-заголовки учитывают SameSite, неизменяемый кэш применяется только к файлам с хешем в имени.
- Первичные данные администратора удаляются только после успешной смены пароля. Межсайтовые cookie сессии поддерживаются при явном включении.

## Core и сертификаты

- В комплект входит `sing-box-extended v1.13.14-extended-2.5.4`.
- WireGuard IPC отдаёт состояние peers для AmneziaWG. Жизненный цикл core и IPC endpoint используют общую синхронизацию, поэтому endpoint не закрывается во время запроса.
- После частичного запуска core откатывает уже выполненные действия. Одновременные вызовы закрытия выполняют операцию один раз и получают сохранённый результат.
- Наблюдатели Clash снова получают логи. Уровни panic и fatal выполняют штатное завершение после записи сообщения.
- Чтение наборов правил закрывает файлы и zlib-потоки, отклоняет обрезанные данные, неверную контрольную сумму и байты после объявленного конца.
- Продление сертификата повторяет применение сохранённой пары после ошибки. Сертификат и закрытый ключ публикуются одной полной версией.
- Telegram backup проверяет фиксированные параметры Argon2 до вычисления ключа и учитывает отмену при создании снимка, шифровании и загрузке.
- В описаниях провайдеров поддерживаются пользовательские HTTP headers, а поле `providers` в группе принимает одно значение или список.
- REALITY сообщает версию клиента `26.7.11`. На серверах с ограничением `maxClientVer: 1.8.1` нужно поднять верхнюю границу.

## Выпуск и установка

- Релизные задания проверяют тег, исходный коммит, состояние релиза, метаданные архивов и контрольные суммы. Опубликованный тег нельзя повторно использовать с другими файлами.
- Пакеты Linux и Windows собираются из точного тега. Workflow сверяет состав архивов и архитектуру, сканирует файлы, публикует SPDX SBOM и подтверждение происхождения сборки.
- Docker-публикация проверяет каждую архитектуру и запускает итоговую smoke-проверку по неизменяемому digest платформы.
- Образ Compose и версия frontend-пакета по умолчанию равны `1.0.8`.

## Обновление

Установщик сохраняет базу и настройки панели. При обычном запуске создаётся таблица списаний провайдера. Ручное изменение конфигурации не требуется.

Команда для Linux:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.0.8/install.sh \
  | sudo bash -s -- v1.0.8
```

Если вы уже вошли как `root`:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.0.8/install.sh) \
  v1.0.8
```

Проверьте версию и службу:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

Первая команда должна показать `1.0.8`, команда `systemctl` - `active`.

Сервер в цикле перезапусков после перехода с beta8 на beta9 нельзя обновить из панели. Используйте команду выше. Не удаляйте `/usr/local/s-ui/db` и `/etc/s-ui` во время восстановления.

Beta10 и beta11 не могут завершить обновление через панель до стабильной 1.0.8, пока выбран канал `beta`: стабильный архив содержит корректный манифест `main`, но эти версии сравнивают его с выбранным каналом и выводят `update manifest is invalid`. Перед проверкой и установкой 1.0.8 переключите канал на **Main (стабильные)** либо используйте команду выше. Если beta10 предлагает beta9, не устанавливайте это понижение.
