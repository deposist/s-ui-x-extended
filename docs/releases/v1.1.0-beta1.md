# S-UI-X Extended v1.1.0-beta1

Version 1.1.0-beta1 fixes panel startup in browsers that block storage, corrects the page language attribute, and adds two hardening checks to the self-updater. It does not change the database schema or runtime configuration.

## Fixed

- In Chrome with "Block all cookies" enabled, reading `localStorage` throws a `SecurityError`. Startup code read stored preferences before the app could render, so the first read aborted boot and the panel showed a blank page. All preference access now goes through a storage wrapper that catches the failure and keeps values in an in-memory copy for the session. Theme, language, table page sizes, and sidebar state work again, and a write that fails on a quota error keeps its value in the session copy.
- The `lang` attribute of the page was hardcoded to `zh-CN` regardless of the interface language. It now follows the selected locale (`en`, `ru`, `fa`, `vi`, `zh-cn`, `zh-tw`) and updates when the language changes. Screen readers pick the correct pronunciation. Until the app applies the saved locale, the attribute is `en`.
- The self-updater's artifact downloader followed redirects without checking the scheme. It now refuses a redirect that would move the transfer from HTTPS to plain HTTP. GitHub's own downloads never do this; the check closes the path in case a redirect endpoint ever behaves differently.
- A release tag from the GitHub API passed only through `TrimSpace` before it was interpolated into the download URL template. A tag must now normalize to a valid release version (semver, lowercase prerelease identifiers, no build metadata). A tag that fails validation is reported as no release for the channel. An attacker would need write access to the repository to control tags, so this is defense in depth.
- New tests cover the storage wrapper (denied access, quota failure, memory fallback), the redirect refusal, and tag validation, including traversal-shaped tags such as `../../other-repo`.

## Upgrade

Users of 1.0.9 and the 1.0.9 beta series can install this release from the console:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.0-beta1/install.sh \
  | sudo bash -s -- v1.1.0-beta1
```

If you are already logged in as `root`:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.0-beta1/install.sh) \
  v1.1.0-beta1
```

After installation, check the version and service:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

The first command must report `1.1.0-beta1`, and `systemctl` must print `active`. The installer preserves `/usr/local/s-ui/db` and `/etc/s-ui`.

This is a beta release. Test it on a non-critical server before using it in production.

# S-UI-X Extended v1.1.0-beta1

Версия 1.1.0-beta1 исправляет запуск панели в браузерах, которые блокируют хранилище, правильный атрибут языка страницы и добавляет две проверки глубины защиты в модуль самообновления. Схема базы и рабочая конфигурация не меняются.

## Исправления

- В Chrome с включённой настройкой «Блокировать все файлы cookie» чтение `localStorage` вызывает `SecurityError`. Код запуска читал сохранённые настройки до отрисовки интерфейса, поэтому первое же чтение прерывало загрузку и панель показывала пустую страницу. Теперь весь доступ к настройкам идёт через обёртку хранилища, которая перехватывает сбой и хранит значения в памяти до конца сессии. Тема, язык, размер страниц таблиц и состояние боковой панели снова работают, а запись, упавшая из-за лимита хранилища, сохраняет значение в копии на сессию.
- Атрибут `lang` страницы был жёстко задан как `zh-CN` независимо от языка интерфейса. Теперь он следует выбранной локали (`en`, `ru`, `fa`, `vi`, `zh-cn`, `zh-tw`) и обновляется при смене языка. Скринридеры выбирают правильное произношение. Пока приложение не применило сохранённый язык, атрибут равен `en`.
- Загрузчик артефактов в модуле самообновления переходил по redirect без проверки схемы. Теперь он отклоняет redirect, который переводит передачу с HTTPS на открытый HTTP. Сами загрузки GitHub так не делают; проверка закрывает путь на случай иного поведения точки перенаправления.
- Тег релиза из API GitHub проходил только `TrimSpace`, после чего подставлялся в шаблон URL загрузки. Теперь тег обязан нормализоваться в корректную версию релиза (semver, строчные идентификаторы prerelease, без метаданных сборки). Тег, не прошедший проверку, трактуется как отсутствие релиза в канале. Чтобы управлять тегами, нужен доступ на запись в репозиторий, так что это мера глубины защиты.
- Новые тесты покрывают обёртку хранилища (запрещённый доступ, сбой по лимиту, запасная память), отказ от redirect и валидацию тегов, включая теги вида `../../other-repo`.

Пользователи 1.0.9 и бета-серии 1.0.9 могут установить релиз из консоли:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.0-beta1/install.sh \
  | sudo bash -s -- v1.1.0-beta1
```

Если вы уже вошли как `root`:

```sh
bash <(curl -fLsS \
```
