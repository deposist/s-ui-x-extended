# S-UI-X Extended v1.0.6-beta3

This prerelease adds a separate Sudoku Split Private Key field for each panel client. The server still runs one unchanged Sudoku inbound with its Master Public Key.

## Per-client Sudoku delivery

The client editor now accepts an optional 128-character hexadecimal Split Private Key under **Config → Sudoku**. When set, the key is used only for that client's `sudoku://` link, its QR code, and the Sudoku outbound in JSON subscriptions. An empty field keeps the previous behavior and uses the inbound key.

Generate a split key on a trusted administrator machine with the official Sudoku CLI:

```bash
sudoku -keygen -more <MASTER_PRIVATE_KEY>
```

The panel does not ask for or store the Master Private Key.

Backend validation is authoritative. The field accepts either an empty value or exactly 64 decoded bytes written as 128 hexadecimal characters. Both 32-byte halves must be canonical Ed25519 scalars. Accepted uppercase input is stored in lowercase. Invalid values are rejected without echoing the submitted key.

JSON subscription assembly uses a field-scoped credential map. Client data may replace only `outbound.key`; server address, port, AEAD, table, HTTP mask, routing, dialer, and tag remain controlled by the inbound template. The stored inbound options and `OutJson` are not modified.

Client-key changes rebuild that client's local links, keep external links, and invalidate that client's subscription cache. They do not reload the Sudoku inbound or restart the core. Backup and restore preserve the key through the existing `Client.Config` column.

## Security limits

A Sudoku Split Private Key is not an independently revocable password. Each split key can reconstruct equivalent master authority. Removing or disabling a client in the panel does not invalidate a key already imported into an application.

Full revocation requires rotating the inbound master pair and issuing new split keys to every remaining client. This release does not add Sudoku per-client traffic accounting or reliable online/offline status.

## Compatibility

No database migration is required. Clients without a Sudoku client key continue to use the inbound-key fallback. The `sing-box-extended` dependency, Sudoku adapter, handshake, and server-side user model are unchanged; Sudoku remains a keyless server inbound with no `users` array.

## Verification

The release was checked with the full Go test suite and vet, frontend unit tests, ESLint, and a production frontend build. Tests cover key validation, API bypass attempts, link and JSON isolation for two clients, fallback behavior, scoped cache invalidation, no core reload, audit redaction, and real database backup/restore preservation.

A live two-client connection test was not run because a compatible Sudoku client executable was not available in the release environment.
