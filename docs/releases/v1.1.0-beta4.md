# S-UI-X Extended v1.1.0-beta4

Version 1.1.0-beta4 fixes two dead ends reported on beta3: a telegram backup passphrase locked behind unreadable key material, and a call outbound without a join link that crash-looped the core. The database schema is unchanged.

## Fixed

- Saving a new telegram backup passphrase failed with `save: secret setting decrypt failed` whenever the stored old value could not be decrypted anymore. The value may end up in that state after key material changes between panel generations, for example when the panel once ran without `SUI_SECRETBOX_KEY` and later picked it up from the environment file. The save path read the old value only to decide whether to write a change audit event, and aborted on the read, which blocked the one action that repairs the secret. An unreadable stored value is now logged as a warning and treated as changed, so entering a new passphrase in the UI overwrites the broken one. No manual database editing is needed anymore.
- A call outbound saved without a `join_link` made every core start fail with `initialize outbound ... missing join_link`, and sing-box restart-looped until the row was deleted from the database by hand. The outbound form now marks the field required for call and explains that the link comes from the host side of a room (the panel logs `call[...]: join_link=...` when a call inbound creates a room). The panel also rejects such saves server-side with an explanatory error. If your config is already poisoned, delete the call outbound on the Outbounds page and the core recovers after the restart cooldown.

## Upgrade

Users of the 1.1.0 beta series, 1.0.9, and the 1.0.9 betas can install this release from the console:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.0-beta4/install.sh \
  | sudo bash -s -- v1.1.0-beta4
```

If you are already logged in as `root`:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.0-beta4/install.sh) \
  v1.1.0-beta4
```

After installing, check the version and the service:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

The first command should print `1.1.0-beta4`, and `systemctl` should report `active`. The installer preserves `/usr/local/s-ui/db` and `/etc/s-ui`.

If the core on your server is restart-looping with `missing join_link`, delete the call outbound on the Outbounds page after the upgrade; the core recovers on its own after the cooldown.

This is a beta release. Test it on a non-critical server before using it in production.

# S-UI-X Extended v1.1.0-beta4 (Русский)

Версия 1.1.0-beta4 исправляет два тупика, о которых сообщили на beta3: passphrase для telegram-бэкапа, запертый за нечитаемым ключевым материалом, и call-outbound без ссылки подключения, отправлявший ядро в цикл перезапусков. Схема базы данных не меняется.

## Исправления

- Сохранение нового passphrase для telegram-бэкапа падало с `save: secret setting decrypt failed`, если старое сохранённое значение больше не расшифровывалось. Такое значение возникает после смены ключевого материала между поколениями панели, например когда панель какое-то время работала без `SUI_SECRETBOX_KEY`, а потом получила его из файла окружения. Путь сохранения читал старое значение только чтобы решить, писать ли событие аудита об изменении, и прерывался на этом чтении, блокируя единственное действие, которым секрет чинится. Теперь нечитаемое старое значение пишется в журнал предупреждением и считается изменённым: ввод нового passphrase в интерфейсе перезаписывает сломанный. Править базу вручную больше не нужно.
- Call-outbound, сохранённый без `join_link`, ломал каждый старт ядра ошибкой `initialize outbound ... missing join_link`, и sing-box перезапускался по кругу, пока строку не удаляли из базы вручную. Форма outbound'ов теперь помечает поле обязательным для call и поясняет, что ссылку даёт сторона-хост комнаты (панель пишет `call[...]: join_link=...` в журнал, когда call-inbound создаёт комнату). Панель также отклоняет такие сохранения на сервере с объяснением. Если конфиг уже отравлен, удалите call-outbound на странице Outbounds, и ядро восстановится после cooldown.

## Обновление

Пользователи бета-серии 1.1.0, 1.0.9 и бет 1.0.9 могут установить релиз из консоли:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.0-beta4/install.sh \
  | sudo bash -s -- v1.1.0-beta4
```

Если вы уже вошли как `root`:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.0-beta4/install.sh) \
  v1.1.0-beta4
```

После установки проверьте версию и службу:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

Первая команда должна вывести `1.1.0-beta4`, а `systemctl` должен напечатать `active`. Установщик сохраняет `/usr/local/s-ui/db` и `/etc/s-ui`.

Если ядро на вашем сервере перезапускается по кругу с ошибкой `missing join_link`, после обновления удалите call-outbound на странице Outbounds; ядро восстановится само после cooldown.

Это бета-релиз. Проверьте его на некритичном сервере, прежде чем использовать в продакшене.
