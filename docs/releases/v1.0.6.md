# S-UI-X Extended v1.0.6

Version 1.0.6 brings the Sudoku and mieru delivery work from the beta series into the stable channel. It also fixes QR delivery for full AmneziaWG 2.0 configs.

## Automatic Sudoku client keys

When you create a Sudoku inbound without a key, the backend generates a canonical Ed25519 master scalar. The panel stores it as `master_key`, derives the public inbound `key`, and keeps the private value out of sing-box, links, QR codes, and subscriptions.

Assigning a client to that inbound creates a 128-character Split Private Key for that client/inbound pair. Clients assigned to several Sudoku inbounds get a different key for each one. The panel picks the matching key when it builds a `sudoku://` link or JSON subscription.

The split-key map is maintained automatically:

- assigning a Sudoku inbound creates the missing key;
- changing the inbound master key replaces incompatible client keys;
- removing an inbound removes its stale client-key entry;
- editing unrelated client fields keeps valid keys unchanged.

Legacy Sudoku PSK and public-key inbounds keep the shared-key fallback. Client records written by v1.0.6-beta3 with a single `sudoku.key` are migrated into the per-inbound map the next time they are saved.

A Sudoku Split Private Key is not independently revocable. Anyone holding one has equivalent master authority. Full revocation still requires rotating the inbound master pair and issuing fresh keys to the remaining clients.

## Sudoku and mieru links

The panel now emits the upstream client link formats alongside JSON subscriptions:

- `sudoku://` uses the compact base64url JSON payload understood by Sudoku clients;
- `mierus://` uses mieru's simple URL format with per-client credentials and inbound-controlled transport settings.

Older clients assigned before link support was added are repaired automatically. The panel performs a one-time lazy backfill when it has the real operator hostname, and Settings includes a manual action to rebuild all client links and QR codes.

The Sudoku HTTP-mask mode is easier to find in the inbound editor. The selector explains the empty/default behavior, and the recommended preset makes legacy mode explicit.

## AmneziaWG 2.0 QR delivery

Full AWG 2.0 configurations could exceed the panel's old 1500-byte limit, leaving the QR dialog with an empty image. The renderer now relies on the QR codec's actual capacity at Low error correction instead of imposing that extra cap.

Rendered client configs include J1, J2, J3, and Itime. QR failures return real HTTP statuses, and the client dialog shows the server error with a pointer to the `.conf` download instead of trying to display JSON as an image.

## AmneziaWG environment key

The console menu can generate `AWG_KEY_ENC` on systems updated through the web panel, where `install.sh` may not have run. It keeps an existing key unless the operator confirms rotation, and it replaces an existing env-file value instead of adding a duplicate.

## Upgrade notes

- No database migration is required.
- Existing Sudoku and mieru assignments are repaired without a manual client re-save.
- Existing legacy Sudoku configurations remain usable.
- For automatic per-client Sudoku keys, create a new Sudoku inbound without entering a key. Existing PSK/public-key inbounds intentionally retain shared-key behavior.
- Do not rotate `AWG_KEY_ENC` after managed AWG devices exist unless you intend to replace their stored key material.

## Verification

The release was checked with the complete Go test suite, `go vet`, race-enabled Sudoku tests, frontend unit tests, ESLint, and a production frontend build. Coverage includes split-key generation and master recovery, per-inbound selection, master rotation, stale-key cleanup, core-config secret filtering, link and JSON delivery, cache invalidation, legacy fallback, backup/restore, and AWG QR error handling.
