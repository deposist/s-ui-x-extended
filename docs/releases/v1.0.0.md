# s-ui-x-extended v1.0.0

This is the first stable release of s-ui-x-extended. It follows the `1.0.0-beta` line and keeps the panel on upstream s-ui-x `v1.5.10-beta7` parity while running on the `shtorm-7/sing-box-extended` core.

## Highlights

- Extended protocol coverage in the panel: Sudoku, TrustTunnel, MASQUE, OpenVPN, MTProxy, WireGuard/WARP endpoints, DHCP DNS transport, `block`, native `bond`, and native core failover.
- Panel-owned outbound groups with provider-backed membership, validation, previews, and capability metadata.
- Panel-managed failover with runtime state, health snapshots, provider health, bounded realtime events, and a Nexus overview health widget.
- Explicit failover all-down policies. Direct fallback is not used unless an administrator selects it.
- Full option coverage tracking against sing-box-extended option structs. The generated matrix has zero unexplained missing fields.
- Advanced inbound, outbound, endpoint, and protocol-specific fields are represented in TypeScript and UI where they are safe for panel editing.
- `/api/capabilities` reports build tags and type availability for the running binary, so the UI disables protocol types that are not compiled in.
- Release workflows now build artifacts with the supported protocol tag set. Sudoku, TrustTunnel, MASQUE, and OpenVPN are present in official Linux and Windows artifacts.
- English and Russian configuration guides are available in `docs/INSTRUCTIONS-EN.md` and `docs/INSTRUCTIONS-RU.md`.

## Upgrade notes

No manual database migration is needed. The application runs the normal migration chain on startup and sets `settings.version` to `1.0.0`.

Panel-managed failover changes the active member for new connections only. Existing sessions may break during a switch.

Native core failover is named `core-failover` in the panel. The generated core configuration serializes it as native `type: failover`.

Direct fallback remains opt-in for failover all-down handling.

## Verification

The release branch passed backend, frontend, capability, option coverage, and diff checks. The beta9 release candidate was smoke-tested using real GitHub release artifacts before this stable release was prepared:

- Linux amd64 artifact started on an Ubuntu GitHub Actions runner and returned `/api/capabilities` with Sudoku, TrustTunnel, MASQUE, and OpenVPN available.
- Windows amd64 artifact started locally with an isolated database and returned the same capability result.
- All Linux artifact checksums matched.
- Linux and Windows artifacts contained the required build tags in embedded Go build metadata.
