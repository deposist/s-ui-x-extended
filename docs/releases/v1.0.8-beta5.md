# S-UI-X Extended v1.0.8-beta5

Version 1.0.8-beta5 tightens the failure paths around database writes, restores, and self-update. It is a beta release. Test it on a non-critical server before relying on it for a production panel.

## Security and updates

- Self-update validates the HTTPS release metadata, archive name, version, platform, and SHA-256 digest before the installed binary can be replaced.
- Releases without the manifest are not offered through self-update.
- The release workflow creates and publishes the metadata manifest beside every Linux archive.
- `golang.org/x/text` was updated to 0.39.0, and hostname validation rejects invalid UTF-8 before IDNA processing.
- Frontend build dependencies were updated. `npm audit --audit-level=moderate` reports no vulnerabilities.

## Database, durability, and recovery

- Database restore now uses a maintenance barrier. Panel requests, subscription requests, and cron work wait while restore drains active database work and swaps the SQLite handle.
- Restore rollback routes no longer deadlock on their own request lease.
- Selective backups read from one source snapshot and run SQLite integrity, foreign-key, and TLS sentinel checks before they are returned.
- Traffic counters, pending IP observations, token-use updates, and audit batches keep their data until a database commit succeeds. Failed writes are retried or put back into the pending queue.
- Scheduled jobs stop with a bounded wait, and application startup rolls back components that were already started if a later startup step fails.
- An x-ui import that commits successfully but cannot checkpoint now returns a warning instead of reporting the whole import as failed.

## Panel behavior

- The initial admin credential file is consumed only after a successful password change under the bootstrap contract.
- Stats polling stops when the modal closes or unmounts. Logs and Changes clear their loading state after failed requests.
- Independent components no longer cancel each other's identical GET requests.
- QR subscription checks are labelled as a best-effort request. The UI no longer presents opaque cross-origin responses as HTTP success.
- API payloads preserve valid values such as `false`, `0`, and an empty string.

## Deployment

- The default Compose file points to `ghcr.io/deposist/s-ui-x:v1.0.8-beta5`.
- nftables privileges are opt-in through `docker-compose.nftables.yml`; the base Compose file does not add Linux capabilities or a TUN device.

## Upgrade notes

- No database migration is required.
- Docker runtime validation was not run here because Docker is unavailable in the release environment. Review the opt-in nftables profile before enabling it.
