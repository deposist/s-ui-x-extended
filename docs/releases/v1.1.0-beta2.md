# S-UI-X Extended v1.1.0-beta2

Version 1.1.0-beta2 takes managed AmneziaWG out of the Paid Subscriptions page, provisions the device encryption key automatically, and converts the old single-endpoint AWG mode on first start. The database schema is unchanged.

## Changed

- Managed AmneziaWG no longer lives on the Paid Subscriptions page. The status line moved to a new "AmneziaWG 3.0" tab in panel Settings and is served from `api/awg/status`; the old `api/paidsub/awg/status` route keeps answering for anything that still calls it. To use AWG, enable "Managed AWG server" on a WireGuard endpoint, assign the server to clients, and create devices in the client card. The paid module is not needed for any of this. Its Telegram bot keeps working and now always operates on the endpoints assigned to each client.

## Added

- The panel provisions the AmneziaWG device encryption key (`AWG_KEY_ENC`) on start when it is missing. It first reuses the environment value, then a valid key stored in `/etc/s-ui/secretbox.env` (or the file named in `SUI_SECRETBOX_ENV_FILE`), and generates a new key only when neither exists. An existing key is never rotated, because rotating it would make stored device keys unreadable. Web-panel updates swap the binary without running the installer; the next start now repairs the missing key by itself instead of failing device operations with `awg: AWG encryption key is unavailable`. On Windows, set the variable in the service environment or point `SUI_SECRETBOX_ENV_FILE` at a file.

## Removed

- The single-endpoint managed AWG mode behind the "Enable managed AWG devices" switch. On the first start after the upgrade the panel converts such setups by itself: the tagged endpoint receives managed metadata, existing devices are re-pointed to it, and clients keep their access rows. The conversion is idempotent. When the endpoint with the configured tag is gone, or a device address falls outside the endpoint subnet, the panel logs a warning naming the endpoint and the problem, leaves the settings as they are, and retries on the next start. This release also fixes a beta1 defect in which enabling the block always failed with `enabled AWG requires endpoint tag and public endpoint` even when both fields were filled in the same form.

## Upgrade

Users of 1.1.0-beta1, 1.0.9, and the 1.0.9 beta series can install this release from the console:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.0-beta2/install.sh \
  | sudo bash -s -- v1.1.0-beta2
```

If you are already logged in as `root`:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.0-beta2/install.sh) \
  v1.1.0-beta2
```

After installing, check the version and the service:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

The first command should print `1.1.0-beta2`, and `systemctl` should report `active`. The installer preserves `/usr/local/s-ui/db` and `/etc/s-ui`.

If you used the old single-endpoint AWG mode, look for a line about the legacy AWG migration in the journal after the restart; a warning there explains what to fix and the panel retries the conversion on the next start.

This is a beta release. Test it on a non-critical server before using it in production.

# S-UI-X Extended v1.1.0-beta2 (Русский)

Версия 1.1.0-beta2 переносит управляемый AmneziaWG со страницы платных подписок в настройки панели, создаёт ключ шифрования устройств автоматически и конвертирует старый режим одного эндпоинта при первом запуске. Схема базы данных не меняется.

## Изменения

- Управляемый AmneziaWG больше не живёт на странице платных подписок. Строка состояния переехала на вкладку «AmneziaWG 3.0» в настройках панели и отдаётся через `api/awg/status`; старый маршрут `api/paidsub/awg/status` продолжает отвечать. Чтобы пользоваться AWG, включите «Управляемый AWG-сервер» на эндпоинте WireGuard, назначьте сервер клиентам и создавайте устройства в карточке клиента. Платный модуль для этого не нужен. Его Telegram-бот работает как раньше и теперь всегда оперирует эндпоинтами, назначенными клиенту.

## Добавлено

- Панель создаёт ключ шифрования устройств AmneziaWG (`AWG_KEY_ENC`) при запуске, если его нет. Сначала берётся значение из окружения, затем корректный ключ из `/etc/s-ui/secretbox.env` (или файла из `SUI_SECRETBOX_ENV_FILE`), и новый ключ генерируется, только если нигде не нашёлся. Существующий ключ не ротируется: смена сделала бы сохранённые ключи устройств нечитаемыми. Обновление через веб-панель заменяет бинарник без запуска установщика, и следующий запуск теперь сам чинит отсутствующий ключ вместо ошибки `awg: AWG encryption key is unavailable` в операциях с устройствами. В Windows задайте переменную в окружении службы или укажите файл через `SUI_SECRETBOX_ENV_FILE`.

## Удалено

- Переключатель «Enable managed AWG devices» и режим одного управляемого эндпоинта. При первом запуске после обновления панель сама конвертирует такие настройки: эндпоинт с указанным тегом получает метаданные управляемого сервера, устройства перепривязываются к нему, клиенты сохраняют строки доступа. Конвертацию можно повторять без последствий. Если она не удалась (эндпоинт с тегом исчез или адрес устройства не попадает в подсеть эндпоинта), панель пишет в журнал предупреждение с именем эндпоинта и причиной, оставляет настройки как есть и повторит попытку при следующем запуске. Заодно исправлен дефект beta1, при котором включение блока всегда заканчивалось ошибкой `enabled AWG requires endpoint tag and public endpoint`, даже когда оба поля были заполнены в той же форме.

## Обновление

Пользователи 1.1.0-beta1, 1.0.9 и бета-серии 1.0.9 могут установить релиз из консоли:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.0-beta2/install.sh \
  | sudo bash -s -- v1.1.0-beta2
```

Если вы уже вошли как `root`:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.0-beta2/install.sh) \
  v1.1.0-beta2
```

После установки проверьте версию и службу:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

Первая команда должна вывести `1.1.0-beta2`, а `systemctl` должен напечатать `active`. Установщик сохраняет `/usr/local/s-ui/db` и `/etc/s-ui`.

Если вы пользовались старым режимом одного эндпоинта, после перезапуска найдите в журнале строку о миграции legacy AWG; предупреждение там объяснит, что поправить, и панель повторит конвертацию при следующем запуске.

Это бета-релиз. Проверьте его на некритичном сервере, прежде чем использовать в продакшене.
