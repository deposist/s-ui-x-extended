# S-UI-X Extended v1.1.0

Version 1.1.0 contains the work released in the 1.1.0 beta series after version 1.0.9. Managed AmneziaWG moves into panel settings with automatic device keys and obfuscation presets, call outbounds and the telegram backup passphrase get fixes that end two core crash loops, and the panel gains storage-safe startup plus two self-updater hardening checks.

## Managed AmneziaWG

- Managed AmneziaWG no longer depends on the Paid Subscriptions page. The status line lives on a new "AmneziaWG 3.0" tab in panel Settings and is served from `api/awg/status`; the old `api/paidsub/awg/status` route keeps answering for anything that still calls it. Enable "Managed AWG server" on a WireGuard endpoint, assign the server to clients, and create devices in the client card. The paid module is not involved in this flow, and its Telegram bot keeps working on the endpoints assigned to each client.
- The panel provisions the device encryption key (`AWG_KEY_ENC`) on start when it is missing. It reuses the environment value first, then a valid key from `/etc/s-ui/secretbox.env` (or the file named in `SUI_SECRETBOX_ENV_FILE`), and generates a new key only when neither exists. An existing key is never rotated. This closes the gap where a web-panel update replaced the binary without running the installer and device operations failed with `awg: AWG encryption key is unavailable`. On Windows, set the variable in the service environment or point `SUI_SECRETBOX_ENV_FILE` at a file.
- The old single-endpoint mode behind the "Enable managed AWG devices" switch is gone. On the first start after the upgrade the panel converts such setups by itself: the tagged endpoint receives managed metadata, existing devices are re-pointed to it, and clients keep their access rows. The conversion is idempotent. If the endpoint with the configured tag is missing, or a device address falls outside the endpoint subnet, the panel logs a warning naming the endpoint and the problem, leaves the settings as they are, and retries on the next start.
- An endpoint with "Managed AWG server" enabled can be saved again after it has devices. The guard compared peers byte by byte, and a form round-trip reorders JSON keys and reformats whitespace, so every edit failed with `managed AWG endpoint peers are controlled by the device manager` although the peers were not touched. Peers are now compared as a set: normal edits (MTU, DNS, public endpoint) go through, and editing the peers themselves is still rejected.
- Two buttons in the Amnezia block of the endpoint form apply obfuscation presets. "Recommended" applies a curated profile: balanced junk padding, S values that keep the four packet sizes distinct and stay at or above 12, the stock init packet prefix, and fixed timings. "Hardened (randomized)" generates the whole set on the server with crypto/rand: headers, junk, padding, and init packet values. Devices must re-download their config after obfuscation changes; the form shows this warning.
- When "Managed AWG server" is switched on and the public endpoint field is empty, the form suggests the panel's own hostname with the listen port. The suggestion follows listen port changes until the field is edited by hand. Stored values are never overwritten, and loopback addresses are never suggested.

## Panel startup and self-update

- In Chrome with "Block all cookies" enabled, reading `localStorage` throws a `SecurityError`, and startup code read stored preferences before the app could render, so the panel showed a blank page. Preference access now goes through a storage wrapper that catches the failure and keeps values in an in-memory copy for the session. Theme, language, table page sizes, and sidebar state work again.
- The page `lang` attribute follows the selected interface language instead of a hardcoded `zh-CN`, so screen readers pick the correct pronunciation. Until the app applies the saved locale, the attribute is `en`.
- The self-updater's artifact downloader refuses a redirect that would move the transfer from HTTPS to plain HTTP, and a release tag from the GitHub API must normalize to a valid version before it is placed in a download URL. A tag that fails validation is reported as no release. Both checks are defense in depth: controlling tags or redirect endpoints already requires write access to the repository.
- New tests cover the storage wrapper, the redirect refusal, and tag validation, including traversal-shaped tags such as `../../other-repo`.

## Call outbounds and telegram backup

- Saving a call outbound no longer stores a `server` field that the core schema does not have. Every core start failed with `json: unknown field "server"` and sing-box restart-looped until the row was deleted from the database by hand. The outbound form no longer shows the address and port fields for call, because call joins a room through `join_link` and has no dial target, and the panel rejects such saves server-side with an error that explains the cause.
- A call outbound saved without a `join_link` made every core start fail with `initialize outbound ... missing join_link`. The form now marks the field required for call and explains that the link comes from the host side of a room; the panel logs `call[...]: join_link=...` when a call inbound creates a room. Server-side validation rejects missing links. If your config is already poisoned, delete the call outbound on the Outbounds page and the core recovers after the restart cooldown.
- The core start cooldown log printed `15ns seconds`. A Go duration division kept the duration type, so the number rendered in nanoseconds. The line now prints the real duration.
- Saving a new telegram backup passphrase failed with `save: secret setting decrypt failed` whenever the stored value could not be decrypted anymore. The save path read the old value only to decide whether to write a change audit event, and aborted on the read, which blocked the one action that repairs the secret. An unreadable stored value is now logged as a warning and treated as changed, so the new passphrase overwrites the broken one. No manual database editing is needed.

## Upgrade

The installer preserves the panel database and configuration. The database schema is unchanged; legacy AWG setups convert on the first start after the upgrade.

Run on Linux:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.0/install.sh \
  | sudo bash -s -- v1.1.0
```

If you are already logged in as `root`:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.0/install.sh) \
  v1.1.0
```

Check the installed version and service state:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

The first command must report `1.1.0`, and `systemctl` must print `active`.

Beta users can update to stable 1.1.0 directly from the panel: the panel validates the stable archive against its `main` manifest, so no channel switch is required. If your server is restart-looping with `missing join_link` or `unknown field "server"`, delete the call outbound on the Outbounds page after the upgrade; the core recovers on its own after the cooldown.

# S-UI-X Extended v1.1.0 (Русский)

Версия 1.1.0 включает изменения всей линейки beta после 1.0.9. Управляемый AmneziaWG переезжает в настройки панели с автоматическим ключом устройств и пресетами обфускации, call-outbound и passphrase telegram-бэкапа получают исправления, завершающие два цикла перезапусков ядра, а панель обзаводится запуском без хранилища и двумя проверками глубины защиты в самообновлении.

## Управляемый AmneziaWG

- Управляемый AmneziaWG больше не зависит от страницы платных подписок. Строка состояния живёт на новой вкладке «AmneziaWG 3.0» в настройках панели и отдаётся через `api/awg/status`; старый маршрут `api/paidsub/awg/status` продолжает отвечать для всего, что его вызывает. Включите «Управляемый AWG-сервер» на эндпоинте WireGuard, назначьте сервер клиентам и создавайте устройства в карточке клиента. Платный модуль в этом потоке не участвует, а его Telegram-бот работает на эндпоинтах, назначенных каждому клиенту.
- Панель создаёт ключ шифрования устройств (`AWG_KEY_ENC`) при запуске, если его нет. Сначала берётся значение из окружения, затем корректный ключ из `/etc/s-ui/secretbox.env` (или файла из `SUI_SECRETBOX_ENV_FILE`), и новый ключ генерируется, только если нигде не нашёлся. Существующий ключ не ротируется. Это закрывает пропуск, при котором обновление через веб-панель заменяло бинарник без запуска установщика, и операции с устройствами падали с `awg: AWG encryption key is unavailable`. В Windows задайте переменную в окружении службы или укажите файл через `SUI_SECRETBOX_ENV_FILE`.
- Старого режима одного эндпоинта за переключателем «Enable managed AWG devices» больше нет. При первом запуске после обновления панель сама конвертирует такие настройки: эндпоинт с указанным тегом получает метаданные управляемого сервера, устройства перепривязываются к нему, клиенты сохраняют строки доступа. Конвертацию можно повторять без последствий. Если эндпоинт с тегом исчез или адрес устройства не попадает в подсеть эндпоинта, панель пишет в журнал предупреждение с именем эндпоинта и причиной, оставляет настройки как есть и повторяет попытку при следующем запуске.
- Эндпоинт с включённым «Управляемым AWG-сервером» снова сохраняется после появления устройств. Гвард сравнивал пиры побайтово, а раунд-трип через форму переупорядочивает ключи JSON и переформатирует пробелы, поэтому каждое редактирование падало с `managed AWG endpoint peers are controlled by the device manager`, хотя пиры никто не трогал. Пиры теперь сравниваются как множество: обычные правки (MTU, DNS, публичный адрес) проходят, а изменение самих пиров по-прежнему отклоняется.
- Две кнопки в блоке Amnezia формы эндпоинта применяют пресеты обфускации. «Рекомендуемые» применяют выверенный профиль: сбалансированный junk-паддинг, значения S, при которых четыре размера пакетов остаются различными и не опускаются ниже 12, стандартный префикс init-пакета и фиксированные тайминги. «Усиленные (рандом)» генерируют весь набор на сервере через crypto/rand: заголовки, junk, паддинг и значения init-пакетов. После смены обфускации устройствам нужно перекачать конфиг; форма показывает это предупреждение.
- При включении «Управляемого AWG-сервера», если поле публичного адреса пустое, форма подставляет хост самой панели с портом listen_port. Подсказка следует за изменениями listen_port, пока поле не отредактировано вручную. Сохранённые значения не перезаписываются, петлевые адреса не подставляются.

## Запуск панели и самообновление

- В Chrome с включённой настройкой «Блокировать все файлы cookie» чтение `localStorage` вызывает `SecurityError`, а код запуска читал сохранённые настройки до отрисовки интерфейса, поэтому панель показывала пустую страницу. Теперь доступ к настройкам идёт через обёртку хранилища, которая перехватывает сбой и хранит значения в памяти до конца сессии. Тема, язык, размер страниц таблиц и состояние боковой панели снова работают.
- Атрибут `lang` страницы следует выбранному языку интерфейса вместо жёстко заданного `zh-CN`, и скринридеры выбирают правильное произношение. Пока приложение не применило сохранённый язык, атрибут равен `en`.
- Загрузчик артефактов в модуле самообновления отклоняет redirect, который переводит передачу с HTTPS на открытый HTTP, а тег релиза из API GitHub обязан нормализоваться в корректную версию, прежде чем попадёт в URL загрузки. Тег, не прошедший проверку, трактуется как отсутствие релиза. Обе проверки глубины защиты: управление тегами и точками перенаправления и так требует доступа на запись в репозиторий.
- Новые тесты покрывают обёртку хранилища, отказ от redirect и валидацию тегов, включая теги вида `../../other-repo`.

## Call-outbound и telegram-бэкап

- Сохранение call-outbound больше не записывает поле `server`, которого нет в схеме ядра. Каждый старт ядра падал с `json: unknown field "server"`, и sing-box перезапускался по кругу, пока строку не удаляли из базы вручную. Форма outbound'ов больше не показывает поля адреса и порта для call, потому что call подключается к комнате через `join_link` и не имеет адреса для подключения, а панель отклоняет такие сохранения на сервере с объяснением причины.
- Call-outbound, сохранённый без `join_link`, ломал каждый старт ядра ошибкой `initialize outbound ... missing join_link`. Форма теперь помечает поле обязательным для call и поясняет, что ссылку даёт сторона-хост комнаты; панель пишет `call[...]: join_link=...` в журнал, когда call-inbound создаёт комнату. Серверная проверка отклоняет отсутствие ссылки. Если конфиг уже отравлен, удалите call-outbound на странице Outbounds, и ядро восстановится после cooldown.
- Лог cooldown старта ядра печатал `15ns seconds`. Деление длительностей в Go сохраняло тип длительности, и число выводилось в наносекундах. Теперь печатается реальная длительность.
- Сохранение нового passphrase для telegram-бэкапа падало с `save: secret setting decrypt failed`, если старое сохранённое значение больше не расшифровывалось. Путь сохранения читал старое значение только чтобы решить, писать ли событие аудита об изменении, и прерывался на этом чтении, блокируя ровно то действие, которым секрет чинится. Теперь нечитаемое старое значение пишется в журнал предупреждением и считается изменённым, и новый passphrase перезаписывает сломанный. Править базу вручную не нужно.

## Обновление

Установщик сохраняет базу и настройки панели. Схема базы данных не меняется; legacy-настройки AWG конвертируются при первом запуске после обновления.

Команда для Linux:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.0/install.sh \
  | sudo bash -s -- v1.1.0
```

Если вы уже вошли как `root`:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.0/install.sh) \
  v1.1.0
```

Проверьте версию и службу:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

Первая команда должна показать `1.1.0`, команда `systemctl` - `active`.

Пользователи beta могут обновиться до стабильной 1.1.0 напрямую из панели: панель проверяет стабильный архив по манифесту `main`, поэтому переключение канала не требуется. Если сервер перезапускается по кругу с ошибкой `missing join_link` или `unknown field "server"`, после обновления удалите call-outbound на странице Outbounds; ядро восстановится само после cooldown.
