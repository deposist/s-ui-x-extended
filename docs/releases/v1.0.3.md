# S-UI-X Extended v1.0.3

v1.0.3 adds AmneziaWG obfuscation tooling (validation, server-side randomize, presets), per-endpoint client config overrides, per-device expiry, and a Russia-direct routing preset. It also carries the fixes for AWG device creation from the panel, the upgrade path from v1.0.2-beta1, the self-update rollback, and sudoku inbound assignment.

## AmneziaWG obfuscation

- The endpoint form validates Amnezia parameters before saving. Values 0-4 for H1-H4 are rejected: they are the vanilla WireGuard message types, so a config that uses them carries no header masking at all (the old panel default `h1:1..h4:4` did exactly that). Overlapping H1-H4 ranges are rejected because the AWG receive path tells packet types apart by matching the header against the configured ranges; with an overlap the handshake never completes and neither side reports an error. The same applies to padded packet sizes: S1+148, S2+92, S3+64 and S4+32 must all differ (this covers the known S1+56=S2 case). Validation blocks the save; there is no override switch, because a saved invalid combination produces a tunnel that silently fails to come up.
- A Randomize button fills H1-H4 with four non-overlapping ranges generated on the server with crypto/rand, matching the bounds the official Amnezia client generator uses. Enabling Amnezia on an endpoint now requests the same generation instead of writing the old static defaults. The generation endpoint is `GET /api/awg/obfuscation/random`.
- Obfuscation presets in the endpoint form: Balanced for wired and home networks, Mobile for carriers whose DPI reacts to large junk packets (values follow the amneziawg-installer ADVANCED.md table), and Custom for manual control. A preset sets only the junk parameters (Jc, Jmin, Jmax); headers stay unique per endpoint. With Balanced active, Randomize also regenerates the junk parameters.
- The form shows tuning hints: lower Jmax on mobile networks, lower the MTU when large downloads stall, and check server CPU softirq load before blaming the channel. Editing obfuscation parameters on an existing endpoint shows a warning that provisioned devices must re-download their config or rescan the QR code.

## Client config overrides

- A managed AWG endpoint can override the `AllowedIPs` and `PersistentKeepalive` lines in rendered device configs. This enables client-side split tunneling, such as sending only foreign prefixes through the tunnel, which server-side rules cannot do: the client decides which packets enter the tunnel before the server sees them. Empty values keep the previous behavior (`0.0.0.0/0, ::/0` and 25 seconds), so existing configs render byte-for-byte identically.
- Every AllowedIPs entry must be a valid CIDR prefix. Entries with line breaks are rejected during validation and dropped again in the renderer, since a newline inside an INI value would start a new directive. Keepalive accepts 0 to 3600 seconds.
- The form notes the usual caveat of IP-based splitting: CDN caches hosted on local ISP ranges can end up outside the tunnel.

## Per-device expiry

- A device can be created with an expiry date. When the date passes, the reconciler removes the peer from the interface; the device row remains and keeps occupying its device-limit slot until deleted. Extending the date and letting the reconciler run restores the peer.
- Rotation and config download stop working for an expired device. The panel shows an "expires in N days" chip that turns into "expired"; the Telegram device card shows the same term. Devices created from the bot have no expiry.
- The `expires_at` column is added automatically on upgrade; existing devices get 0, which means no expiry.

## Routing preset

- The regional presets drawer has a new card for managed AWG endpoints: Russia direct. One click creates a remote geoip-ru rule-set and a route rule scoped to the endpoint's inbound, so traffic from AWG devices to Russian IP addresses leaves the server directly while everything else follows the existing rules. Removing the preset cleans up the rule and drops the rule-set once no endpoint uses it. Custom rules are not touched.

## Fixed

- Creating an AmneziaWG 2.0 device from the client form failed with `awg: invalid request`. The API handler only accepted JSON bodies, while the panel sends form-encoded requests. The handler now picks the decoder based on the request Content-Type, so both the panel and JSON API clients work.
- Upgrading from v1.0.2-beta1 crashed the panel on every start with `no such column: endpoint_id`. Startup rebuilt the `awg_devices` table and lost columns in the process, then tried to index a column that was never added. The table is now left alone once it exists, and indexes are created only after the column migrations have run. Installations that hit the crash recover on their own after this upgrade.
- The self-update rollback never worked on Linux. Restoring the backup wrote into the running binary, which the kernel rejects with `text file busy`. The restore now renames the backup into place, the same way the forward swap installs a new binary.
- A sudoku inbound never appeared in the client edit form's inbound selector, so it could not be assigned to any client (#4). The panel treated "assignable" as "has per-user credentials", and sudoku has none: its clients share a single inbound-level key and receive the outbound through the JSON subscription. Assignability is now derived from the protocol manifest, so a sudoku inbound can be assigned like any other and shows its assigned clients in the inbound list. The sing-box config generation for sudoku is unchanged.

## Also in this release

- Assigning a client to an endpoint that is not a managed AWG server is now rejected instead of silently accepted. Such assignments had no effect: no device manager ever served them.
- Database backups now include the `client_endpoint_access` table, so client-to-server assignments survive a restore.
- An endpoint managed through the legacy global AWG settings is marked as managed in the endpoint list again, and its peers get the same edit protection as endpoints managed through the endpoint form.
- The auto-register inbound selector in paid subscriptions now only offers inbounds that can actually deliver something to a client. Transparent and local types (direct, tun, tproxy and similar) are no longer listed; selecting them had no effect.

## Upgrade

Upgrade normally. The `expires_at` column is added automatically; endpoints saved before this release keep working and are validated on their next edit. Note for existing AWG endpoints: if yours still uses the old default headers (H1=1 to H4=4), open the endpoint, press Randomize and save, then have the devices re-download their configs. The old values provide no header masking.

# S-UI-X Extended v1.0.3

v1.0.3 добавляет инструменты обфускации AmneziaWG (валидация, серверная генерация случайных значений, пресеты), переопределение клиентского конфига на уровне endpoint, срок действия устройств и пресет маршрутизации «Россия напрямую». Также включены исправления создания AWG-устройств из панели, пути обновления с v1.0.2-beta1, отката self-update и назначения sudoku-инбаундов.

## Обфускация AmneziaWG

- Форма endpoint проверяет параметры Amnezia перед сохранением. Значения 0-4 для H1-H4 отклоняются: это типы сообщений обычного WireGuard, конфиг с ними не маскирует заголовки вовсе (старый дефолт панели `h1:1..h4:4` делал именно это). Пересекающиеся диапазоны H1-H4 отклоняются, потому что приёмная сторона AWG различает типы пакетов по попаданию заголовка в настроенный диапазон; при пересечении рукопожатие не завершается, и ни одна сторона не сообщает об ошибке. То же с размерами пакетов: S1+148, S2+92, S3+64 и S4+32 должны различаться (это покрывает известный случай S1+56=S2). Валидация блокирует сохранение без обходного переключателя: сохранённая невалидная комбинация даёт туннель, который молча не поднимается.
- Кнопка случайных значений заполняет H1-H4 четырьмя непересекающимися диапазонами, сгенерированными на сервере через crypto/rand, в тех же границах, что и генератор официального клиента Amnezia. Включение Amnezia на endpoint теперь запрашивает такую же генерацию вместо старых статичных значений. Эндпоинт генерации: `GET /api/awg/obfuscation/random`.
- Пресеты обфускации в форме endpoint: «Сбалансированный» для проводных и домашних сетей, «Мобильный» для операторов, чей DPI реагирует на крупные мусорные пакеты (значения по таблице ADVANCED.md установщика amneziawg-installer), и «Ручной». Пресет задаёт только параметры мусора (Jc, Jmin, Jmax); заголовки остаются уникальными для каждого endpoint. При активном «Сбалансированном» кнопка случайных значений перегенерирует и параметры мусора.
- Форма показывает советы по настройке: уменьшить Jmax в мобильных сетях, снизить MTU при потерях на крупных файлах, проверить softirq-нагрузку CPU сервера прежде чем винить канал. Изменение параметров обфускации на существующем endpoint показывает предупреждение: устройства должны перескачать конфиг или пересканировать QR-код.

## Переопределение клиентского конфига

- Управляемый AWG endpoint может переопределять строки `AllowedIPs` и `PersistentKeepalive` в конфигах устройств. Это клиентский сплит-туннелинг, например только зарубежные префиксы через туннель, чего серверные правила сделать не могут: клиент решает, какие пакеты идут в туннель, до того как их увидит сервер. Пустые значения сохраняют прежнее поведение (`0.0.0.0/0, ::/0` и 25 секунд), существующие конфиги рендерятся байт в байт как раньше.
- Каждый элемент AllowedIPs должен быть валидным CIDR-префиксом. Значения с переводами строк отклоняются при валидации и повторно отбрасываются в рендерере: перевод строки внутри INI-значения начал бы новую директиву. Keepalive принимает от 0 до 3600 секунд.
- Форма честно предупреждает о нюансе деления по IP: CDN-кэши на адресах местных провайдеров могут оказаться вне туннеля.

## Срок действия устройств

- Устройство можно создать с датой истечения. Когда дата проходит, реконсайлер снимает peer с интерфейса; запись устройства остаётся и продолжает занимать слот лимита до ручного удаления. Продление даты с последующим reconcile восстанавливает peer.
- Ротация и скачивание конфига для истёкшего устройства перестают работать. Панель показывает бейдж «истекает через N дн.», который превращается в «истекло»; карточка устройства в Telegram показывает тот же срок. Устройства из бота создаются бессрочными.
- Колонка `expires_at` добавляется автоматически при обновлении; существующие устройства получают 0, то есть без срока.

## Пресет маршрутизации

- В панели региональных пресетов появилась карточка для управляемых AWG-эндпоинтов: «Россия напрямую». Один клик создаёт remote rule-set geoip-ru и правило маршрутизации, привязанное к inbound этого endpoint: трафик устройств AWG к российским IP-адресам выходит с сервера напрямую, остальной идёт по существующим правилам. Отключение пресета убирает правило и удаляет rule-set, когда его не использует ни один endpoint. Пользовательские правила не затрагиваются.

## Исправлено

- Создание устройства AmneziaWG 2.0 из формы клиента завершалось ошибкой `awg: invalid request`. Обработчик API принимал только JSON, а панель отправляет form-encoded запросы. Теперь декодер выбирается по Content-Type запроса, поэтому работают и панель, и JSON-клиенты API.
- Обновление с v1.0.2-beta1 роняло панель при каждом запуске с ошибкой `no such column: endpoint_id`. При старте таблица `awg_devices` пересоздавалась с потерей колонок, после чего создание индекса ссылалось на колонку, которой не было. Существующая таблица больше не трогается, а индексы создаются только после миграций колонок. Установки, попавшие на этот сбой, восстанавливаются сами после обновления.
- Откат self-update не работал на Linux. Восстановление бэкапа писало в работающий бинарник, что ядро отклоняет с ошибкой `text file busy`. Теперь бэкап переименовывается на место, тем же способом, каким устанавливается новый бинарник.
- Sudoku-инбаунд не появлялся в селекторе инбаундов формы клиента, поэтому его нельзя было назначить ни одному клиенту (#4). Панель считала «назначаемым» только инбаунд с per-user учётными данными, а у sudoku их нет: клиенты делят один общий ключ и получают outbound через JSON-подписку. Назначаемость теперь выводится из манифеста протоколов, поэтому sudoku-инбаунд назначается как любой другой и показывает назначенных клиентов в списке инбаундов. Генерация sing-box конфига для sudoku не изменилась.

## Также в релизе

- Назначение клиента на endpoint, который не является управляемым AWG-сервером, теперь отклоняется, а не принимается молча. Такие назначения не имели эффекта: их не обслуживал ни один менеджер устройств.
- Таблица `client_endpoint_access` включена в резервные копии базы, поэтому назначения клиентов на серверы переживают восстановление.
- Endpoint, управляемый через старые глобальные настройки AWG, снова помечается как управляемый в списке endpoint'ов, а его peers защищены от ручного редактирования, как и у endpoint'ов, управляемых через форму.
- Селектор авторегистрации в платных подписках теперь предлагает только инбаунды, которые что-то доставляют клиенту. Прозрачные и локальные типы (direct, tun, tproxy и подобные) больше не показываются; их выбор не имел эффекта.

## Обновление

Обновляйтесь обычным способом. Колонка `expires_at` добавляется автоматически; эндпоинты, сохранённые до этого релиза, продолжают работать и проверяются при следующем редактировании. Замечание для существующих AWG-эндпоинтов: если у вас всё ещё старые дефолтные заголовки (H1=1 до H4=4), откройте endpoint, нажмите кнопку случайных значений и сохраните, затем перескачайте конфиги на устройствах. Старые значения не маскируют заголовки.
