# s-ui-x-extended v1.0.0-beta9

This beta follows v1.0.0-beta8 and fixes the release build configuration. Beta8 added the panel-side protocol coverage, but the official release workflows still used an older, smaller build tag list. As a result, some downloaded binaries could not enable Sudoku, TrustTunnel, MASQUE, or OpenVPN even though the UI and capability manifest knew about them.

## What's new

- Linux release artifacts now build with the full supported protocol tag set. This includes Sudoku, TrustTunnel, MASQUE, OpenVPN, MTProxy, WireGuard/WARP endpoints, DHCP DNS transport, and the extended service tags used by this fork.
- Windows release artifacts and local Windows build scripts now use the same supported protocol tag set.
- A regression test now compares release workflows and build scripts with `core/capabilities/protocols.json`, so future protocol additions cannot silently disappear from release artifacts.
- Naive outbound remains conditional on Linux release targets that prepare the cronet/naive toolchain. Windows builds keep `with_naive_outbound` and package the pinned `libcronet.dll`.
- The `shtorm-7/sing-box-extended` dependency was not modified.

## Notes for operators

- No manual database migration is needed. The binary runs the normal migration chain on startup and updates `settings.version` to `1.0.0-beta9`.
- If you installed beta8 from GitHub release assets and could not select Sudoku, TrustTunnel, MASQUE, or OpenVPN, upgrade to beta9.
- The expected runtime check is `/api/capabilities`: `with_sudoku`, `with_trusttunnel`, `with_masque`, and `with_openvpn` should be `true`, and the related protocol rows should have `available: true`.
