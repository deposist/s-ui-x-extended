# s-ui-x-extended v1.0.0-beta8

This beta builds on v1.0.0-beta7. It keeps the upstream s-ui-x v1.5.10-beta7 panel work and adds the panel control-plane work needed for sing-box-extended protocols, groups, providers, and advanced options.

## What's new

- Added panel-managed outbound groups and provider-backed group membership. Selector, URLTest, fallback, and panel failover groups now share validation, tag reference checks, preview support, and capability metadata.
- Added panel failover state and operational health data. The panel records outbound and provider probe results, publishes bounded health snapshots, and shows them on the Nexus overview page.
- Added explicit all-down failover policy handling. The default is conservative and keeps the current member. Direct fallback is used only when the operator selects it.
- Added type coverage for missing core types: outbound `block`, native core failover outbound, inbound `bond`, and native core failover inbound.
- Added advanced inbound, outbound, and endpoint fields to the panel types and editors, including shared listen options, outbound `domain_strategy`, WireGuard, WARP, and Tailscale advanced options.
- Added provider capability metadata to `/api/capabilities` and the generated frontend capability types.
- Added an option coverage matrix and drift test. The matrix is generated from the sing-box-extended option structs and currently has zero unexplained missing fields.
- Kept all changes in the panel layer. The `shtorm-7/sing-box-extended` dependency was not modified.

## Notes for operators

- No manual database migration is needed. The binary runs the normal migration chain on startup and updates `settings.version` to `1.0.0-beta8`.
- Panel-managed failover switches new connections. Existing sessions can still break when the active member changes.
- Native core failover is exposed as a separate panel type, `core-failover`, so it does not collide with the panel-managed `failover` group.
- Direct fallback remains opt-in. Existing failover groups keep the conservative all-down behavior unless changed by an admin.
