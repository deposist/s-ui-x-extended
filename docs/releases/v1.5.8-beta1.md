# Release Notes: v1.5.8-beta1

Release date: 2026-06-11
**EN**

v1.5.8-beta1 extends no-restart apply to all core objects managed by the panel. Saving inbounds, outbounds, endpoints, and services now hot-replaces only the affected object inside the running sing-box core instead of restarting the whole core. Unrelated active connections stay alive, and if hot apply fails, the panel safely falls back to a full restart so the running configuration does not become stale.

The release also adds stricter protection against broken references: deleting or renaming an outbound, endpoint, or managed inbound is now blocked if that tag is still used anywhere else in the configuration. The error shows exactly where the tag is referenced, making it easier to fix the config before saving. Additional reliability fixes prevent unnecessary restarts on no-op config saves, serialize core synchronization to avoid save/restart races, and fix a latent data race in the panel restart scheduler.

No frontend changes, database migration, or manual configuration changes are required.

**RU**

v1.5.8-beta1 расширяет применение изменений без рестарта на все основные объекты, которыми управляет панель. Сохранение Inbounds, Outbounds, endpoint'ов и сервисов теперь горячо заменяет только изменённый объект внутри работающего ядра sing-box, вместо перезапуска всего ядра. Активные соединения через незатронутые объекты продолжают работать, а если горячее применение не удалось, панель безопасно откатывается на полный рестарт, чтобы не оставить ядро со старой конфигурацией.

Также добавлена строгая защита от сломанных ссылок: удаление или переименование outbound'а, endpoint'а или managed inbound'а теперь блокируется, если этот тег ещё используется где-то в конфигурации. Ошибка показывает все места, где есть ссылка на тег, поэтому конфиг проще исправить до сохранения. Дополнительно исправлены лишние рестарты при сохранении конфига без изменений, сериализована синхронизация ядра, чтобы избежать гонок между save/restart, и устранена скрытая data race в планировщике рестарта панели.

Изменений фронтенда, миграции базы и ручных изменений конфигурации не требуется.
