# S-UI-X Extended v1.0.9-beta3

Version 1.0.9-beta3 fixes a database restore deadlock. While the panel dashboard is open, its realtime WebSocket holds a shared read lease on the database for the whole session. Restore takes an exclusive lock before replacing SQLite and waits for all readers, so with a socket open it never started. The panel froze, API requests queued behind the lock, and the maintenance job logged `cron: skip` every two seconds. A manual service restart closed the socket, which is why it looked like the cure.

The WebSocket now keeps the lease only for the handshake, and maintenance jobs skip ticks silently while a restore runs. Restore finishes with the dashboard open. The database schema and runtime configuration do not change.

## Fixed

- Database restore no longer deadlocks behind an open realtime WebSocket. The socket previously held a shared maintenance lease for its whole lifetime, so the exclusive restore lock could never be acquired. The lease now ends right after the handshake, before the connection loop.
- Cron maintenance jobs no longer block or spam `cron: skip` while a restore runs. A tick that collides with a restore is skipped, and the job runs on the next tick.
- A restore started from the panel completes with the dashboard open. No service restart is needed.
- Regression tests open a WebSocket, start a restore, and assert both finish while the socket stays connected.

## Upgrade

Users of 1.0.9-beta2 can install this release from the console:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.0.9-beta3/install.sh \
  | sudo bash -s -- v1.0.9-beta3
```

If you are already running as `root`:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.0.9-beta3/install.sh) \
  v1.0.9-beta3
```

After installation, check the version and service:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

The first command must report `1.0.9-beta3`, and `systemctl` must print `active`. The installer preserves `/usr/local/s-ui/db` and `/etc/s-ui`.

This is a beta release. Test it on a non-critical server before relying on it in production.

# S-UI-X Extended v1.0.9-beta3

Версия 1.0.9-beta3 исправляет зависание восстановления базы данных. Пока открыта панель, её веб-сокет (WebSocket) держит общую блокировку чтения базы всё время сессии. Восстановление перед заменой SQLite берёт исключительную блокировку и ждёт всех читателей, поэтому при открытом сокете оно не начиналось вовсе. Панель замирала, запросы к API вставали в очередь, а служебное задание каждые две секунды писало в лог `cron: skip`. Ручной перезапуск службы закрывал сокет, поэтому казалось, что он помогает.

Теперь сокет держит блокировку только во время рукопожатия, а служебные задания молча пропускают такт, пока идёт восстановление. База восстанавливается при открытой панели, без перезапуска. Схема базы и рабочая конфигурация не меняются.

## Исправления

- Открытый веб-сокет панели больше не блокирует восстановление базы. Раньше сокет держал общую блокировку обслуживания всё время жизни, и восстановление не могло получить исключительную блокировку. Теперь блокировка заканчивается сразу после рукопожатия, до цикла соединения.
- Служебные задания cron больше не блокируются и не спамят `cron: skip`, пока идёт восстановление. Такт, совпавший с восстановлением, пропускается, а задание выполняется на следующем такте.
- Восстановление, начатое из панели, завершается при открытой панели. Перезапуск службы не нужен.
- Регрессионные тесты открывают веб-сокет, запускают восстановление и проверяют, что оба завершаются, пока сокет остаётся подключённым.
