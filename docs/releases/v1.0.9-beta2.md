# S-UI-X Extended v1.0.9-beta2

Version 1.0.9-beta2 fixes WARP Endpoint creation. The registration code expected the peer endpoint from Cloudflare to be a bare IP with a real port, but the API returns a domain in the `host` field and a placeholder `:0` port in the `v4` and `v6` fields. Every genuine response failed validation and the endpoint could not be saved. The panel now reads the actual Cloudflare shape. The database schema and runtime configuration do not change.

## Fixed

- WARP registration now accepts the peer endpoint as Cloudflare returns it. The `v4`, `v6`, and `host` fields are all read, and a domain in `host` no longer counts as invalid.
- The `v4` and `v6` forms carry port `0` as a placeholder. When the panel sees it, it substitutes the first usable port from the `ports` list, or the well-known WARP port `2408` when the list is empty. A real port in the range is kept as is.
- The panel prefers a literal `v4` or `v6` address over the hostname. That keeps the core from resolving the peer through its own DNS at startup, which would be a problem when DNS itself runs over the tunnel. The hostname remains a fallback for API versions that omit the addresses.
- Regression tests cover the Cloudflare endpoint shapes and the invalid cases they reject.

## Upgrade

Users of 1.0.9-beta1 can install this release from the console:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.0.9-beta2/install.sh \
  | sudo bash -s -- v1.0.9-beta2
```

If you are already running as `root`:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.0.9-beta2/install.sh) \
  v1.0.9-beta2
```

After installation, check the version and service:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

The first command must report `1.0.9-beta2`, and `systemctl` must print `active`. The installer preserves `/usr/local/s-ui/db` and `/etc/s-ui`.

This is a beta release. Test it on a non-critical server before relying on it in production.

# S-UI-X Extended v1.0.9-beta2

Версия 1.0.9-beta2 исправляет создание WARP Endpoint. Модуль регистрации принимал peer-endpoint от Cloudflare только как голый IP с настоящим портом, а в ответе API домен стоит в поле `host`, порт в `v4` и `v6` равен `0`. Любой реальный ответ не проходил проверку, и endpoint не сохранялся. Теперь панель читает поле как есть. Схема базы и рабочая конфигурация не меняются.

## Исправления

- Регистрация WARP теперь принимает peer-адрес в том виде, в каком его отдаёт Cloudflare. Читаются поля `v4`, `v6` и `host`, домен в `host` больше не считается ошибкой.
- В формах `v4` и `v6` порт `0` это заглушка. Если панель его видит, она берёт первый рабочий порт из списка `ports`, а при пустом списке использует стандартный порт WARP `2408`. Настоящий порт из диапазона сохраняется как есть.
- Панель предпочитает литеральный адрес `v4` или `v6`, а не имя хоста. Так core не резолвит peer через собственный DNS при старте, что сломало бы работу, когда DNS идёт поверх туннеля. Имя хоста остаётся запасным вариантом для версий API без адресов.
- Добавлены регрессионные тесты на формы endpoint от Cloudflare и на мусор, который отклоняется.
