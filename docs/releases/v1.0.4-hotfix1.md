# S-UI-X Extended v1.0.4-hotfix1

Hotfix for the AWG device key-encryption key. Managed AmneziaWG devices could not be created because the key was never provisioned, so the panel returned `awg: AWG encryption key is unavailable`.

## Fixed

- The systemd installer now generates `AWG_KEY_ENC` on install and upgrade, the same way it already handles `SUI_SECRETBOX_KEY` and `SUI_COOKIE_KEY`. Without this key the device manager cannot seal per-device WireGuard private and preshared keys, and every device operation failed with `awg: AWG encryption key is unavailable`. The key is written to the panel environment file (`/etc/s-ui/secretbox.env`) and shown once during a fresh generation.

## Behavior

- An existing `AWG_KEY_ENC` is never regenerated. Rotating it after devices exist would make their stored key material undecryptable, so re-running the installer for an upgrade leaves the key untouched. A value already present in the environment is adopted and persisted instead of generating a new one.

## Installing this hotfix

This build is versioned `1.0.4-hotfix1`. A prerelease suffix sorts below `1.0.4` in the panel version comparison, so the in-panel auto-update on a `1.0.4` install will not offer it. Install it explicitly by re-running the installer or updating from the tag.

## Manual step for existing installs

If your panel already logged `awg: AWG encryption key is unavailable` and you installed before this release, add the key once and restart:

```
umask 077
printf 'AWG_KEY_ENC=%s\n' "$(head -c 32 /dev/urandom | base64 | tr -d '\r\n')" >> /etc/s-ui/secretbox.env
chmod 600 /etc/s-ui/secretbox.env
systemctl restart s-ui
```

Only do this if no managed AWG devices exist yet. If devices were already created under a working key, restore that same key instead; a new key cannot decrypt their stored material. Keep the value backed up alongside `SUI_SECRETBOX_KEY`.
