# S-UI-X Extended v1.0.8-beta11

Version 1.0.8-beta11 fixes two faults in the beta self-update path and a release-publication timing failure. No database migration or manual configuration change is required.

## Fixed

- The beta channel now compares the numeric part of compact prerelease names. Versions such as `beta10` and `beta11` sort after `beta9`.
- Release publication now retries the GitHub release lookup for a short period after creating a draft. A normal API visibility delay no longer aborts asset reconciliation.
- The updater accepts the numeric `.update-pending` marker written by beta8. During startup it converts the marker to the current transaction format, records the SHA-256 digest of the installed binary and its backup, then continues normal recovery.
- A valid legacy marker keeps automatic rollback protection. Other malformed markers still stop startup because their update state cannot be established safely.

## Console upgrade

Use the console installer for this release. This is required if a beta8 to beta9 update left the service in a restart loop with this error:

```text
self-update recovery: decode pending marker: json: cannot unmarshal number into Go value of type service.pendingUpdateMarker
```

Run:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.0.8-beta11/install.sh \
  | sudo bash -s -- v1.0.8-beta11
```

If you are already logged in as `root`, you can use:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.0.8-beta11/install.sh) \
  v1.0.8-beta11
```

The installer stops the service, replaces the release files, preserves the database and configuration, and starts the service again. Afterward, check the result:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

The first command must report `1.0.8-beta11`, and `systemctl` must print `active`.

## Notes

- Do not delete `/usr/local/s-ui/db` or `/etc/s-ui` while recovering the server.
- This is a beta release. Test it on a non-critical server before using it in production.

# S-UI-X Extended v1.0.8-beta11
Версия 1.0.8-beta11 исправляет две ошибки самообновления бета-канала и сбой публикации релиза при задержке GitHub API. Миграция базы и ручное изменение конфигурации не требуются.

## Исправления

- Бета-канал сравнивает числовую часть компактных названий версий. `beta10` и `beta11` теперь идут после `beta9`.
- После создания черновика публикация несколько раз проверяет его появление в GitHub API. Обычная задержка API больше не прерывает загрузку артефактов.
- Модуль обновления принимает числовой файл `.update-pending`, который создавала beta8. При запуске панель переводит его в текущий формат транзакции, записывает SHA-256 установленного и резервного исполняемых файлов, затем продолжает обычное восстановление.
- Корректный старый файл сохраняет автоматический откат. Другие повреждённые файлы по-прежнему останавливают запуск, потому что безопасно определить состояние обновления по ним нельзя.

## Обновление через консоль

Для этого релиза используйте установщик из консоли. Это обязательно, если после обновления с beta8 на beta9 служба постоянно перезапускается с ошибкой:

```text
self-update recovery: decode pending marker: json: cannot unmarshal number into Go value of type service.pendingUpdateMarker
```

Выполните:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.0.8-beta11/install.sh \
  | sudo bash -s -- v1.0.8-beta11
```

Если вы уже вошли как `root`, подойдёт короткий вариант:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.0.8-beta11/install.sh) \
  v1.0.8-beta11
```

Установщик остановит службу, заменит файлы релиза, сохранит базу и настройки, затем снова запустит службу. После обновления проверьте результат:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

Первая команда должна показать `1.0.8-beta11`, а `systemctl` должен вывести `active`.

## Примечания

- Не удаляйте `/usr/local/s-ui/db` и `/etc/s-ui` при восстановлении сервера.
- Это бета-версия. Сначала проверьте её на некритичном сервере.
