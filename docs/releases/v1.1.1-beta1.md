# S-UI-X Extended v1.1.1-beta1

Version 1.1.1-beta1 fixes two problems reported against 1.1.0: TrustTunnel clients that stayed "connected" while no site opened, and inbound saves that could crash-loop sing-box. No database migration is required.

## Fixed

- Clients assigned to a TrustTunnel (or Mieru) inbound received a subscription with a username but no password. The credential backfill created the per-client config block with the client name only, and the subscription builder drops empty credential fields. The official TrustTunnel client connects and shows Connected anyway, because the TLS handshake succeeds before the first authorized request; the server then rejects every request with `authorization failed`, and no site opens. The panel now generates a random password when it creates the block, and fills in an empty password when the block already exists. To repair an affected client, open the inbound for editing and save it once, then update the subscription on the client.
- Saving certain inbounds could make sing-box restart in a loop with `json: unknown field`. The panel no longer emits fields the inbound option struct does not declare: TrustTunnel no longer emits the outbound-only `quic` switch, Trojan no longer emits `network`, Sudoku keeps its HTTP-mask settings in the inbound schema, and Call omits listen fields. Rows already affected are cleaned when the core config is generated. The panel also validates the generated inbound JSON before committing a save, and validates a restored core config before restarting sing-box; an invalid restore rolls back to the previous database.
- Updated the `github.com/pion/dtls/v3` dependency from 3.1.2 to 3.1.4 (GO-2026-6165, a panic while parsing a crafted ECDHE_PSK ServerKeyExchange). The panel does not call the affected symbols, so this is a hardening update.
- Updated the `github.com/pion/stun/v3` dependency from 3.1.1 to 3.1.5 (GO-2026-6163, a panic on a malformed XOR-MAPPED-ADDRESS attribute). The panel does not call the affected symbols, so this is a hardening update.

## Upgrade

Users of 1.1.0 and the 1.1.0 betas can install this release from the console:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.1-beta1/install.sh \
  | sudo bash -s -- v1.1.1-beta1
```

If you are already logged in as `root`:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.1-beta1/install.sh) \
  v1.1.1-beta1
```

After installing, check the version and the service:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

The first command should print `1.1.1-beta1`, and `systemctl` should report `active`. The installer preserves `/usr/local/s-ui/db` and `/etc/s-ui`.

If you have a TrustTunnel client whose subscription was generated by 1.1.0: after the upgrade, open the inbound in the panel, save it once, and re-download the subscription on the client. The new subscription carries the password that 1.1.0 omitted.

This is a beta release. Test it on a non-critical server before using it in production.

# S-UI-X Extended v1.1.1-beta1 (Русский)

Версия 1.1.1-beta1 исправляет две проблемы, о которых сообщили на 1.1.0: клиенты TrustTunnel оставались «подключёнными», при этом ни один сайт не открывался, и сохранение inbound'ов могло отправить sing-box в цикл перезапусков. Миграция базы данных не требуется.

## Исправления

- Клиенты, назначенные на inbound TrustTunnel (или Mieru), получали подписку с именем пользователя, но без пароля. Заполнение credentials создавало per-client блок конфигурации только с именем клиента, а построитель подписки отбрасывает пустые поля. Официальный клиент TrustTunnel при этом подключается и показывает Connected: TLS-handshake проходит до первого авторизованного запроса, а дальше сервер отклоняет каждый запрос с `authorization failed`, и сайты не открываются. Теперь панель генерирует случайный пароль при создании блока и заполняет пустой пароль, если блок уже существует. Чтобы починить затронутого клиента, откройте inbound на редактирование, сохраните его один раз и обновите подписку на клиенте.
- Сохранение некоторых inbound'ов могло заставить sing-box перезапускаться по кругу с `json: unknown field`. Панель больше не передаёт поля, которых нет в inbound-структуре опций: TrustTunnel больше не пишет исходящий переключатель `quic`, Trojan не пишет `network`, Sudoku хранит настройки HTTP-mask в схеме inbound, а Call не добавляет поля listen. Строки, уже пострадавшие от старого поведения, очищаются при генерации конфига ядра. Панель также проверяет сгенерированный inbound JSON до коммита сохранения и проверяет восстановленный конфиг ядра до перезапуска sing-box; невалидный restore откатывается к предыдущей базе.
- Обновлена зависимость `github.com/pion/stun/v3` с 3.1.1 до 3.1.5 (GO-2026-6163, panic при разборе некорректного атрибута XOR-MAPPED-ADDRESS). Панель не вызывает затронутые символы, так что это обновление на всякий случай.

## Обновление

Пользователи 1.1.0 и бет 1.1.0 могут установить релиз из консоли:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.1-beta1/install.sh \
  | sudo bash -s -- v1.1.1-beta1
```

Если вы уже вошли как `root`:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.1-beta1/install.sh) \
  v1.1.1-beta1
```

После установки проверьте версию и службу:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

Первая команда должна вывести `1.1.1-beta1`, а `systemctl` должен напечатать `active`. Установщик сохраняет `/usr/local/s-ui/db` и `/etc/s-ui`.

Если у вас клиент TrustTunnel с подпиской, сгенерированной панелью 1.1.0: после обновления откройте inbound в панели, сохраните его один раз и заново скачайте подписку на клиенте. В новой подписке будет пароль, которого не было в 1.1.0.

Это бета-релиз. Проверьте его на некритичном сервере, прежде чем использовать в продакшене.

# S-UI-X Extended v1.1.1-beta1 (中文)

版本 1.1.1-beta1 修复了 1.1.0 上报告的两个问题：TrustTunnel 客户端显示已连接但打不开任何网站，以及保存入站可能让 sing-box 陷入重启循环。不需要数据库迁移。

## 修复

- 分配到 TrustTunnel（或 Mieru）入站的客户端拿到的订阅里有用户名但没有密码。凭据回填在创建客户端配置块时只写入了客户端名称，而订阅构建器会丢弃空的凭据字段。官方 TrustTunnel 客户端在这种情况下依然连接并显示 Connected：TLS 握手发生在第一次授权请求之前，随后服务器以 `authorization failed` 拒绝每个请求，网站打不开。现在面板在创建配置块时生成随机密码，配置块已存在时会补上空缺的密码。修复受影响的客户端：在面板里打开该入站并保存一次，然后在客户端上更新订阅。
- 保存某些入站会让 sing-box 以 `json: unknown field` 循环重启。面板不再发送入站选项结构里没有声明的字段：TrustTunnel 不再发送仅用于出站的 `quic` 开关，Trojan 不再发送 `network`，Sudoku 把 HTTP-mask 设置保留在入站 schema 中，Call 不再发送 listen 字段。已受影响的行会在生成核心配置时自动清理。面板在提交保存前校验生成的入站 JSON，在重启 sing-box 前校验恢复的核心配置；校验失败的恢复会回滚到之前的数据库。
- 依赖 `github.com/pion/dtls/v3` 从 3.1.2 升级到 3.1.4（GO-2026-6165，解析构造的 ECDHE_PSK ServerKeyExchange 时 panic）。面板没有调用受影响的符号，属于加固性更新。
- 依赖 `github.com/pion/stun/v3` 从 3.1.1 升级到 3.1.5（GO-2026-6163，解析畸形的 XOR-MAPPED-ADDRESS 属性时 panic）。面板没有调用受影响的符号，属于加固性更新。

```sh
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.1-beta1/install.sh \

```

如果你已经是 `root`：

```sh

  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.1-beta1/install.sh) \
```

安装后检查版本和服务：

第一条命令应输出 `1.1.1-beta1`，`systemctl` 应报告 `active`。安装器会保留 `/usr/local/s-ui/db` 和 `/etc/s-ui`。
