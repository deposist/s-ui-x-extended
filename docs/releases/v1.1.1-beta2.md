# S-UI-X Extended v1.1.1-beta2

Version 1.1.1-beta2 fixes a server crash: saving a TrustTunnel inbound without a TLS configuration stopped sing-box from starting and sent the restart watchdog into a loop. No database migration is required.

The TrustTunnel protocol requires TLS at the core level — when sing-box constructs the inbound adapter, it returns `TLS required` if no enabled TLS config is attached. The panel's save validation was parse-only and never checked this requirement, so a save with `tls_id=0` passed validation, committed the row, and then sing-box failed to start. The restart watchdog kept retrying every cooldown interval, creating a persistent crash loop until the bad row was deleted.

The panel now rejects such saves at two levels: the frontend OnlyTLS list includes TrustTunnel (blocking the save button), and the server-side save path returns an error before the database commit. The fix covers both the UI and the API/import path.

If you have an affected TrustTunnel inbound from a previous version: edit it, attach a TLS configuration, and save. The inbound will start normally.

## Fixed

- TrustTunnel inbound saves without a TLS template are now rejected before commit, preventing a core restart loop. The protocol manifest (`protocols.json`) now marks TrustTunnel as `onlyTls: true`; the frontend capability list was regenerated and includes TrustTunnel in `OnlyTLS`; the `saveInboundUpsert` path checks `capabilities.TLSRequiredTypes()` and returns an error when the inbound type requires TLS but no TLS template is selected.

## Upgrade

Users of 1.1.1-beta1 and 1.1.0 can install this release from the console:

```sh
curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.1-beta2/install.sh \
  | sudo bash -s -- v1.1.1-beta2
```

If you are already logged in as `root`:

```sh
bash <(curl -fLsS \
  https://raw.githubusercontent.com/deposist/s-ui-x-extended/v1.1.1-beta2/install.sh) \
  v1.1.1-beta2
```

After installing, check the version and the service:

```sh
/usr/local/s-ui/sui -v
systemctl is-active s-ui
journalctl -u s-ui -n 50 --no-pager
```

The first command should print `1.1.1-beta2`, and `systemctl` should report `active`. The installer preserves `/usr/local/s-ui/db` and `/etc/s-ui`.

This is a beta release. Test it on a non-critical server before using it in production.

# S-UI-X Extended v1.1.1-beta2 (Русский)

Версия 1.1.1-beta2 исправляет падение сервера: сохранение inbound TrustTunnel без TLS-конфигурации останавливало sing-box и отправляло watchdog в цикл перезапусков. Миграция базы данных не требуется.

Протокол TrustTunnel требует TLS на уровне ядра — при создании inbound-адаптера sing-box возвращает `TLS required`, если включённая TLS-конфигурация не привязана. Проверка сохранения в панели была parse-only и никогда не проверяла это требование, поэтому сохранение с `tls_id=0` проходило валидацию, строка коммитилась, а sing-box не запускался. Watchdog перезапускал ядро каждые несколько десятков секунд, создавая постоянный краш-луп, пока плохую строку не удаляли вручную.

Теперь панель отклоняет такие сохранения на двух уровнях: фронтенд включает TrustTunnel в список OnlyTLS (блокируя кнопку сохранения), а серверный путь сохранения возвращает ошибку до коммита в базу. Фикс закрывает и UI, и API/импорт.

Если у вас есть затронутый TrustTunnel inbound с предыдущей версии: отредактируйте его, привяжите TLS-конфигурацию и сохраните. Inbound запустится нормально.

## Исправления

- Сохранение inbound TrustTunnel без TLS-шаблона теперь отклоняется до коммита, предотвращая краш-луп ядра. Манифест протоколов (`protocols.json`) помечает TrustTunnel как `onlyTls: true`; фронтендовый список возможностей перегенерирован и включает TrustTunnel в `OnlyTLS`; путь `saveInboundUpsert` проверяет `capabilities.TLSRequiredTypes()` и возвращает ошибку, когда тип inbound требует TLS, а шаблон не выбран.

# S-UI-X Extended v1.1.1-beta2 (中文)

版本 1.1.1-beta2 修复了一个服务器崩溃问题：保存没有 TLS 配置的 TrustTunnel 入站会让 sing-box 无法启动，watchdog 陷入重启循环。不需要数据库迁移。

TrustTunnel 协议在核心层面要求 TLS — sing-box 构造入站适配器时，如果没有启用 TLS 配置，会返回 `TLS required`。面板的保存校验只是解析层校验，从未检查这个要求，因此 `tls_id=0` 的保存能通过校验、提交行数据，然后 sing-box 启动失败。watchdog 每隔几十秒重试一次，形成持续崩溃循环，直到手动删除错误行。

现在面板在两层拒绝此类保存：前端将 TrustTunnel 加入 OnlyTLS 列表（阻止保存按钮），服务端保存路径在数据库提交前返回错误。修复覆盖了 UI 和 API/导入两种路径。

如果你有来自之前版本的受影响的 TrustTunnel 入站：编辑它，添加 TLS 配置，然后保存。入站将正常启动。

## 修复

- 没有 TLS 模板的 TrustTunnel 入站保存现在在提交前被拒绝，避免核心重启循环。协议清单 (`protocols.json`) 将 TrustTunnel 标记为 `onlyTls: true`；前端能力列表已重新生成，包含 TrustTunnel 在 `OnlyTLS` 中；`saveInboundUpsert` 路径检查 `capabilities.TLSRequiredTypes()`，当入站类型要求 TLS 但未选择模板时返回错误。
