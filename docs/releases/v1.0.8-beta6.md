# S-UI-X Extended v1.0.8-beta6

Version 1.0.8-beta6 adds panel-managed regional rule-sets, nested route and DNS conditions, UI and accessibility fixes, and a rebased `sing-box-extended` core. This is a beta. Test it on a non-critical server before using it in production.

## Rule-sets

- The panel downloads regional `.srs` files before saving a preset, verifies them, and writes local paths into the sing-box configuration. Core startup no longer waits on GitHub.
- Downloads accept HTTPS sources only. The direct downloader rejects private and infrastructure addresses at connection time, including redirects and DNS rebinding. A single file is limited to 32 MiB, and one batch to 64 MiB.
- Assets and `rulesets/sources.json` are committed together. A failed download, file replacement, or manifest update rolls the batch back and leaves the last working files in place.
- A daily job refreshes assets listed in the manifest. The authenticated, CSRF-protected `/rulesets/materialize` endpoint downloads either directly or through the outbound selected in the regional preset drawer and carries request cancellation through the download.
- Doctor checks and save-time validation reject missing, non-regular, oversized, or invalid local rule-set files. A materialization error leaves the configuration unchanged.
- Regional presets use an IP-literal DNS-over-HTTPS fallback for non-regional queries. Regional resolvers remain scoped to their geosite rules.

## Route and DNS rules

- The route and DNS editors support recursive `and` and `or` groups. Converting a logical group to a simple rule asks before removing descendants.
- Validation uses the decoded core rule types instead of a frontend approximation. Errors include the exact path to an invalid descendant.
- The endpoint caps the request body at 1 MiB and each route or DNS tree at 64 levels and 4,096 nodes. The UI ignores validation responses superseded by a later validation request or by closing or reloading the editor.
- Saving preserves direct-action dialer options, route options such as `override_gateway`, and DNS action fields such as `disable_cache`, `rewrite_ttl`, and `client_subnet`.

## Panel UI

- List pages distinguish a genuinely empty collection from a search with no matches. Empty collections offer the relevant create or setup action.
- Entity drawers explain which required field or selection is blocking Save.
- The login screen and Settings layout adapt to narrow viewports. Settings tracks unsaved changes, labels units, explains zero values, and gives Save and Restart distinct visual weight.
- The Nexus shell provides logout from both account menus, remembers the collapsed desktop sidebar, and announces server status through a dedicated `role="status"` live region.
- Overview panels provide useful actions when data is absent, keep KPI values on one line, and scroll or resize instead of clipping dense content.
- Page-header search stays synchronized with its parent, and HTTP error messages remain useful for strings, structured payloads, null values, and objects that cannot be serialized as JSON.

## Core

- The bundled core is `sing-box-extended v1.13.14-extended-2.5.4`.
- WireGuard endpoint IPC methods provide the peer state used by AmneziaWG provisioning. Core start, stop, endpoint removal, and IPC access share one lock so an endpoint cannot close during a request.
- The core closes rule-set files and zlib readers after use, which lets Windows replace downloaded `.srs` files.
- Binary rule-set reads reject truncated files, bad zlib checksums, and data after the declared rules.
- REALITY continues to advertise client version `26.7.11`. Current Xray servers default to `minClientVer: 26.3.27`, so the older `1.8.1` value is not used. Legacy servers capped at `maxClientVer: 1.8.1` need that bound updated.
- Provider definitions accept custom HTTP `headers`, and group `providers` accepts one value or a list.
- The `sing-vmess` replacement now matches the core requirement, `0.2.8-extended`.

## Deployment

- The default Compose file points to `ghcr.io/deposist/s-ui-x:v1.0.8-beta6`. Beta5 still pulled the beta4 image despite its release notes.
- `frontend/package.json` and its lockfile are aligned with `config/version`; both were still on beta4.
- nftables privileges remain opt-in through `docker-compose.nftables.yml`. The base Compose file adds no Linux capabilities or TUN device.

## Upgrade notes

- Existing configurations continue to load. Rule-set materialization runs when an operator applies a preset or when the refresh job starts.
- Docker runtime validation was not run because Docker is unavailable in this environment. Review the opt-in nftables profile before enabling it.
