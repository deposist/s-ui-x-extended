# S-UI-X Extended v1.0.4

v1.0.4 is a bugfix release for managed AmneziaWG endpoints. It fixes a core start failure after saving an endpoint and a save-time gap that let a managed endpoint be stored with an address the device manager cannot use.

## Fixed

- Saving any endpoint could stop sing-box from starting with `endpoints[N].awgManaged: json: unknown field "awgManaged"`. The endpoint list adds a panel-only `awgManaged` marker for the frontend, and the frontend sent it back on save. The save path stored the marker inside the endpoint options, which are written into the sing-box config as-is, and sing-box rejects unknown fields. The marker is now stripped before options are stored, and it is also stripped when the config is rendered, so installations that already have the marker in the database recover on their own. No migration is needed.
- A managed AWG endpoint could be saved with a `/32` host address (the default the panel generates for a new WireGuard endpoint). Metadata validation passed, but every reconcile afterwards failed with `managed AWG endpoint address does not match awgSubnet`, and the IP allocator had no room for device addresses. Saving a managed endpoint now checks the options: the first address must be an IPv4 subnet of `/30` or larger, the host address must not be the network or broadcast address, and `listen_port` must be set. Existing endpoints with a `/32` address keep working as plain WireGuard; open the endpoint and widen the address (for example `10.0.0.20/32` to `10.0.0.20/24`) so device management starts working.

## Endpoint form

- Turning on managed mode now widens the generated default `/32` address to `/24`. Only the untouched default is changed; an address you typed yourself stays as-is.
- The public endpoint, DNS, and address fields are validated in the form before the save request is sent. The public endpoint must be `host:port`, DNS must be one or more IP addresses, and the address must contain an IPv4 subnet of `/30` or larger. A failing field shows the reason and the save is blocked, in all four panel languages. The server checks remain authoritative.

## Upgrade notes

- No database migration. Rows that already contain the stray `awgManaged` marker are healed at config render time and cleaned up permanently on the next save of that endpoint.
- If you have a managed endpoint with a `/32` address, edit it once and widen the subnet. The panel will not accept `/32` for managed endpoints anymore.
