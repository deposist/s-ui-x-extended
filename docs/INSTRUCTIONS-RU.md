## 1. Схема связей и зависимостей параметров

Конфигурация sing-box строится по модульному принципу. Все компоненты ссылаются друг на друга через текстовые метки (теги). Изменение одного элемента часто требует корректировки связанных разделов.

```
                    +------------------------------------+
                    |            DNS Settings            |
                    |   (Резолверы и правила запросов)   |
                    +-----------------+------------------+
                                      |
                                      | использует
                                      v
+------------------+        +------------------+        +------------------+
|     Inbounds     |        |      Rules       |        |    Outbounds     |
| (Входящие порты, |------->| (Маршрутизация   |------->| (Выходящие шлюзы |
| протоколы, TLS)  |        | по условиям)     |        |  и прокси-группы)|
+--------+---------+        +------------------+        +--------+---------+
         |                                                       |
         | использует                                            | контролируют
         v                                                       v
+------------------+                                    +------------------+
|   TLS Settings   |                                    |     Limiters     |
|  (Сертификаты /  |                                    | (Ограничения     |
|     Reality)     |                                    | скорости, сессий)|
+------------------+                                    +------------------+
```

### Таблица ключевых связей

| Параметр | На что ссылается | Где настраивается источник | Назначение ссылки |
| :--- | :--- | :--- | :--- |
| **Inbound** (протокол) | TLS Profile | TLS Settings | Включение шифрования, Reality или классического TLS |
| **Inbound** (протокол) | detour | Outbounds | Перенаправление расшифрованного потока (для ShadowTLS) |
| **Outbound** (Failover, Selector) | outbounds | Outbounds (теги других прокси) | Список серверов для балансировки или выбора |
| **Outbound** (прокси) | limiters | Outbounds (тип Limiter) | Подключение лимитов скорости или числа соединений |
| **Rule** (Маршрут) | inbound | Inbounds (теги входящих портов) | Фильтрация по порту поступления пакета |
| **Rule** (Маршрут) | outbound | Outbounds (теги исходящих шлюзов) | Выбор направления для отправки совпавшего трафика |
| **DNS Server** | detour | Outbounds (теги прокси) | Отправка DNS-запросов через защищенный прокси-канал |

## 2. Inbounds (Входящие подключения)

Входящие подключения открывают порты на сервере, через которые клиенты подключаются к прокси. Каждая запись представляет собой отдельную службу со своим сетевым сокетом, типом авторизации и транспортным протоколом.

### Общие настройки прослушивания (Listen Options)
В каждом Inbound, вне зависимости от протокола, присутствует блок параметров сокета. Для доступа к скрытым полям нажмите кнопку "Listen Options" (Параметры прослушивания) в интерфейсе панели.

*   **Listen (Адрес прослушивания):** сетевой IP-адрес интерфейса, на котором открывается служба.
    *   `0.0.0.0` означает слушать все доступные IPv4-интерфейсы. Это стандартный выбор для публичного сервера.
    *   `::` означает слушать все доступные интерфейсы IPv4 и IPv6.
    *   `127.0.0.1` означает сделать службу доступной только внутри самого сервера. Это применяется при установке панели за локальным обратным прокси-сервером вроде Nginx, Apache или Caddy.
*   **Port (Сетевой порт):** число от 1 до 65535. Нельзя создавать два подключения на один и тот же порт, иначе служба не запустится из-за конфликта сокетов.
*   **Detour (Обход / Маршрут перенаправления):** тег другого Inbound, куда пересылается трафик после первичного декодирования. Это критически важное поле для связки ShadowTLS с Shadowsocks.
*   **Bind Interface (Привязка к интерфейсу):** текстовое имя конкретной сетевой карты сервера (например, `eth0` или `wg0`). Заставляет службу принимать трафик только с этого физического или виртуального устройства.
*   **Routing Mark (Метка маршрутизации):** числовой идентификатор пакетов в формате hex (например, `0x2024`). Используется ядром Linux для применения системных правил маршрутизации.
*   **Reuse Addr (Повторное использование адреса):** флаг, позволяющий запускать порт сразу после перезагрузки службы, не дожидаясь, пока операционная система закроет предыдущие сокеты в состоянии TIME_WAIT.
*   **Network Namespace (Сетевое пространство имен / netns):** текстовое имя виртуального пространства Linux, в котором будет запущен сокет. Помогает изолировать трафик на уровне ядра.
*   **TCP Fast Open (TFO):** включение отправки данных в первом пакете SYN при установке TCP-соединения. Ускоряет подключение, но требует поддержки со стороны ядра ОС.
*   **TCP Multi Path:** включение одновременной передачи данных по разным сетевым путям (если на устройстве активно несколько подключений, например, Wi-Fi и LTE).
*   **UDP Fragment:** разрешение на фрагментацию UDP-пакетов для совместимости с каналами, у которых низкий показатель MTU.
*   **UDP NAT Expiration:** время жизни сессии трансляции адресов UDP в минутах. По истечении этого времени неактивная сессия закрывается для экономии ресурсов.
*   **Disable TCP Keep Alive:** отключает регулярную отправку пустых проверочных пакетов в неактивных сессиях.
*   **TCP Keep Alive:** частота отправки проверочных пакетов TCP Keep Alive (задается в формате времени, например, `15s`).
*   **TCP Keep Alive Interval:** интервал между повторными попытками проверки, если предыдущий Keep Alive пакет остался без ответа.

### Расширенные параметры входящих подключений (Inbound Advanced)
Этот блок параметров отвечает за анализ проходящих пакетов и тонкую настройку маршрутизации запросов.

*   **Sniff (Анализ протокола):** перехват заголовков трафика для чтения доменных имен. Помогает ядру узнать, к какому сайту обращается клиент, даже если трафик зашифрован. Это необходимо для работы правил маршрутизации по именам доменов.
*   **Sniff Override Destination:** если включено, оригинальный IP-адрес назначения в заголовке пакета заменяется на IP-адрес, полученный при резолве перехваченного домена.
*   **Sniff Timeout:** время ожидания анализа пакета в миллисекундах (например, `300ms`). Если за это время протокол не распознан, пакет передается далее как неструктурированный поток.
*   **Proxy Protocol:** включает чтение заголовков PROXY protocol (v1 или v2). Позволяет принимать реальный IP-адрес клиента от вышестоящего балансировщика.
*   **Proxy Protocol Accept No Header:** если включено, сервер продолжит обрабатывать соединение, даже если заголовок PROXY protocol не был получен.
*   **Domain Strategy (Стратегия разрешения доменов):**
    *   `prefer_ipv4` означает запрашивать IPv4 и IPv6, но отдавать приоритет IPv4.
    *   `prefer_ipv6` означает отдавать приоритет IPv6.
    *   `ipv4_only` означает запрашивать исключительно IPv4-адреса.
    *   `ipv6_only` означает запрашивать исключительно IPv6-адреса.
*   **UDP Disable Domain Unmapping:** отключает обратное сопоставление доменных имен для UDP-сессий, что повышает скорость обработки в онлайн-играх.

### Настройка Inbounds по протоколам
*   **VLESS:** протокол с минимальными задержками и отсутствием шифрования на уровне прокси (шифрование полностью возлагается на транспортный слой TLS или Reality).
    *   *Обязательные поля:*
        *   `Decryption` (Дешифрование): по умолчанию должно быть установлено значение `none`.
        *   `TLS Profile` (Профиль TLS): выберите созданный профиль из списка TLS Settings для защиты канала. При использовании Reality выберите соответствующий профиль Reality.
*   **VMess:** классический протокол со встроенным шифрованием и авторизацией по UUID.
    *   *Специфичные настройки:*
        *   `UUID` (Уникальный идентификатор): строка-ключ для авторизации клиента.
        *   `Alter ID` (Альтернативный ID): число, определяющее количество виртуальных ID для маскировки (в современных сетях рекомендуется ставить значение `0` во избежание снижения скорости).
        *   `Security` (Алгоритм шифрования): выбор метода шифрования пакетов (`auto`, `none`, `zero`, `aes-128-gcm`, `chacha20-poly1305`). Рекомендуется выбирать `auto`.
        *   `Packet Encoding` (Кодирование пакетов): тип обработки UDP-трафика. Доступны значения `none`, `packetaddr` (упаковка адресов) и `xudp` (оптимизированный UDP).
        *   `Network` (Сеть): выбор транспортного протокола (TCP, gRPC, WebSocket).
        *   `Global Padding` (Глобальное заполнение): добавляет случайный мусор к длине пакетов для усложнения анализа трафика системами глубокого анализа (DPI).
        *   `Authenticated Length` (Авторизованная длина): шифрование длины пакета для защиты от активного сканирования.
*   **Trojan:** протокол, маскирующий трафик под веб-сокеты HTTPS с авторизацией по паролю.
    *   *Специфичные настройки:*
        *   `Fallback Server` (Сервер возврата): IP-адрес (например, `127.0.0.1`), на который перенаправляется пользователь, если он не прошел авторизацию или зашел через обычный браузер. Это маскирует прокси под обычный сайт.
        *   `Fallback Port` (Порт возврата): порт сервера возврата (например, `80` или `443`).
        *   `Fallback for ALPN` (Возврат по протоколам прикладного уровня): таблица перенаправлений в зависимости от заголовка ALPN (например, перенаправление HTTP/1.1 на один порт, а HTTP/2 на другой).
        *   `TLS Profile` (Профиль TLS): обязателен для создания защищенного HTTPS канала.
*   **Shadowsocks:** надежный протокол с симметричным шифрованием и поддержкой современных aead-методов.
    *   *Специфичные настройки:*
        *   `Method` (Метод шифрования): выбор алгоритма. Рекомендуется использовать `2022-blake3-aes-128-gcm` или `2022-blake3-chacha20-poly1305` для максимальной защиты и высокой скорости.
        *   `Password` (Пароль): ключ шифрования. Для методов 2022 года ключ должен генерироваться строго определенной длины (панель генерирует его автоматически по нажатию кнопки генерации).
        *   `Network` (Сеть): выбор поддерживаемых протоколов (TCP, UDP или оба).
        *   `Managed` (Управляемый): флаг, позволяющий панели управлять списком клиентов и лимитами трафика внутри этого порта.
*   **Socks:** протокол для локального использования или работы через другие приложения. Не имеет встроенного шифрования.
    *   *Специфичные настройки:*
        *   `Username` (Имя пользователя): логин авторизации.
        *   `Password` (Пароль): пароль авторизации.
        *   `Version` (Версия): выбор версии протокола (`4`, `4a` или `5`). Версия `5` поддерживает UDP и авторизацию.
        *   `Network` (Сеть): поддерживаемые транспортные протоколы (TCP, UDP).
        *   `UoT` (UDP over TCP): упаковка UDP-запросов в TCP-канал для обхода ограничений провайдеров на UDP-трафик.
*   **Http:** обычный прокси-сервер HTTP. Не рекомендуется использовать для работы через открытый интернет без TLS-шифрования.
    *   *Специфичные настройки:*
        *   `Username` и `Password` для базовой авторизации (Basic Auth).
        *   `Path` (Путь): виртуальный URL-путь проксирования.
        *   `Headers` (Заголовки): пользовательские HTTP-заголовки, которые сервер будет добавлять в ответы.
*   **Mieru:** специализированный протокол, использующий поведенческий анализ для борьбы с блокировками.
    *   *Специфичные настройки:*
        *   `Transport` (Транспорт): тип сетевого транспорта.
        *   `User Hint is Mandatory` (Обязательное имя пользователя): требует от клиента обязательной отправки идентификатора пользователя на этапе подключения.
        *   `Listen Ports` (Порты прослушивания): массив портов, которые протокол будет слушать одновременно.
        *   `Traffic Pattern` (Шаблон трафика): конфигурация маскировки активности.
*   **Sudoku:** протокол со встроенной маскировкой заголовков под HTTP-запросы (HTTP Mask).
    *   *Специфичные настройки:*
        *   `Key` (Ключ): общий секретный ключ для авторизации.
        *   `AEAD Method` (Метод шифрования): выбор алгоритма (`chacha20-poly1305`, `aes-128-gcm` или `none`).
        *   `Table Type` (Тип таблицы): выбор структуры подстановочных таблиц для шифрования.
        *   `Padding Min` и `Padding Max` (Минимальное и максимальное заполнение): диапазон случайного заполнения пакетов мусорными байтами.
        *   `Handshake Timeout` (Таймаут приветствия): время ожидания авторизационных пакетов от клиента.
        *   `Pure Downlink` (Чистый нисходящий канал): оптимизация трафика при передаче от сервера к клиенту.
        *   `Custom Table` и `Custom Tables` (Пользовательские таблицы): задание собственных матриц шифрования для повышения уникальности сигнатуры трафика.
        *   `Disable Http Mask` (Отключить HTTP маскировку): выключает режим мимикрии под HTTP.
        *   `HTTP Mask Mode` (Режим маскировки): выбор формата заголовков HTTP.
        *   `Path Root` (Корневой путь): виртуальный путь в HTTP-запросах.
        *   `Fallback` (Резервный адрес): куда перенаправлять неавторизованные HTTP-запросы.
*   **TrustTunnel:** протокол для создания шифрованных туннелей с тонкой настройкой параметров QUIC.
    *   *Специфичные настройки:*
        *   `Network` (Сеть): выбор поддерживаемых протоколов (TCP, UDP).
        *   `QUIC`: включение транспорта QUIC на базе UDP.
        *   `Congestion Controller` (Контроллер перегрузок): алгоритм управления скоростью передачи пакетов в QUIC (`bbr`, `bbr_standard`, `bbr2`, `bbr2_variant`, `cubic`, `reno`). Рекомендуется выбирать `bbr`.
        *   `BBR Profile` (Профиль BBR): интенсивность работы алгоритма (`standard`, `conservative` для экономии ресурсов или `aggressive` для максимального заполнения канала).
        *   `CWND` (Окно перегрузки): максимальный размер окна отправки пакетов без получения подтверждения от клиента.
*   **SSH:** запуск встроенного сервера SSH для туннелирования.
    *   *Специфичные настройки:*
        *   `Server Version` (Версия сервера): строка идентификации версии SSH.
        *   `Max Auth Tries` (Максимальное число попыток): лимит попыток ввода пароля перед блокировкой сессии.
        *   `Host Key` (Ключ хоста): массив приватных ключей хоста.
        *   `Host Key Path` (Пути к ключам): пути к файлам приватных ключей на сервере.
*   **TUIC:** быстрый протокол на базе QUIC.
    *   *Специфичные настройки:*
        *   `Congestion Control` (Управление очередью): алгоритм QUIC (`cubic`, `new_reno` или `bbr`).
        *   `Zero-RTT Handshake` (Нулевое время установки связи): позволяет отправлять данные сразу при первом пакете без предварительного согласования параметров TLS. Ускоряет загрузку страниц.
        *   `Auth Timeout` (Таймаут авторизации): лимит времени на отправку токена авторизации клиентом в секундах.
        *   `Heartbeat` (Частота пинга): интервал отправки проверочных пакетов для поддержания NAT-сессии открытой на роутере клиента.
*   **MTProxy:** прокси-сервер для мессенджера Telegram с поддержкой FakeTLS.
    *   *Специфичные настройки:*
        *   `Prefer IP` (Предпочитаемый IP): выбор протокола IPv4 или IPv6 для связи с серверами Telegram.
        *   `Concurrency` (Параллелизм): максимальное количество одновременных рабочих потоков.
        *   `Auto Update` (Автообновление): автоматическое скачивание актуального списка IP-адресов серверов Telegram (прокси-нод).
        *   `Domain Fronting Port` (Порт обхода): порт для маскировки под веб-сайт.
        *   `Fronting Host` (Домен обхода): доменное имя, под которое маскируется прокси (например, `cloudflare.com`).
        *   `Proxy Protocol`: включает поддержку PROXY protocol для внешнего веб-сервера.
        *   `Idle Timeout` (Таймаут простоя): время закрытия неактивного соединения.
        *   `Handshake Timeout` (Таймаут приветствия): время на установку защищенного соединения.
        *   `Tolerate Time Skewness` (Допуск расхождения времени): максимальная разница во времени между часами сервера и клиента, при которой разрешено подключение.
        *   `Throttle Max Connections` (Лимит соединений): ограничение максимального числа одновременных подключений.
        *   `Throttle Check Interval` (Интервал проверки лимитов): частота проверки счетчиков подключений.
        *   `Allow Fallback on Unknown DC` (Резерв при неизвестном дата-центре): разрешает перенаправлять запросы на любые доступные серверы Telegram, если целевой дата-центр недоступен.
        *   `Doppelganger URLs` (Домены-двойники): список реальных сайтов для полной имитации TLS-рукопожатий при проверках провайдерами.
        *   `Doppelganger Per Raid` (Число двойников на запрос): количество генерируемых ложных запросов для маскировки.
        *   `Doppelganger Each` (Интервал двойников): частота генерации ложной активности.
        *   `Doppelganger DRS` (Динамический выбор доменов): включение случайного перебора доменов-двойников из списка.
*   **Direct:** прямое прослушивание портов без шифрования с перенаправлением трафика на указанный адрес.
    *   *Специфичные настройки:*
        *   `Network` (Сеть): поддерживаемые транспортные протоколы (TCP, UDP).
        *   `Override Address` (Адрес переопределения): IP-адрес или домен назначения, куда пересылается весь приходящий трафик.
        *   `Override Port` (Порт переопределения): порт получателя.
*   **Tun:** создание виртуальной сетевой карты в системе. Весь трафик сервера на уровне операционной системы направляется внутрь sing-box.
    *   *Специфичные настройки:*
        *   `Addresses` (Адреса): виртуальные IP-адреса интерфейса в формате CIDR через запятую (например, `172.18.0.1/30`).
        *   `Interface Name` (Имя интерфейса): имя создаваемой сетевой карты в системе (по умолчанию `tun0`).
        *   `MTU` (Максимальный размер пакета): размер сетевого пакета. Обычно устанавливается значение `1400` или `1500`.
        *   `UDP Timeout` (Таймаут UDP): время удержания неактивных UDP сессий в минутах.
        *   `Stack` (Сетевой стек): тип обработки пакетов виртуальной карты. Доступны варианты `system` (системный стек ОС), `gvisor` (встроенный виртуальный стек, рекомендуется для стабильности на Linux) или `mixed` (смешанный стек).
        *   `Auto Route` (Автомаршрутизация): автоматическое добавление системных маршрутов в таблицу маршрутизации ОС для перехвата всего трафика.
        *   `Auto Redirect` (Автоматическое перенаправление): перехват всех системных соединений без необходимости ручной настройки правил.
        *   `Strict Route` (Строгий маршрут): предотвращает утечки трафика в обход виртуального интерфейса при переподключениях физических интерфейсов.
        *   `Exclude MPTCP` (Исключить многопутевой TCP): отключает обработку multipath TCP пакетов.
        *   `Fallback Rule Index` (Индекс резервного правила): приоритет правила перенаправления в системном сетевом фильтре.
        *   `Reset Mark` (Метка сброса): маркировка пакетов для сброса соединений при изменении маршрутов.
        *   `Input Mark` (Входная метка) и `Output Mark` (Выходная метка): маркировка входящего и исходящего трафика для корректного разделения потоков в системных таблицах маршрутизации.
        *   `NFQueue`: номер системной очереди Netfilter для обработки пакетов на Linux.
        *   `Keep Lan Direct` (Исключить локальную сеть): добавляет правила, направляющие трафик локальных сетей (например, `192.168.1.0/24`) напрямую в обход туннеля для сохранения доступа к локальным устройствам.
        *   `Rule Set Tunnel` (Списки правил): выбор внешних списков доменов или IP, которые должны направляться строго через этот туннель.
*   **TProxy:** прозрачный прокси-сервер. Используется для перехвата трафика на сетевом уровне без изменения адресов назначения (обычно настраивается совместно с правилами iptables TPROXY на сервере).
    *   *Специфичные настройки:*
        *   `Network` (Сеть): выбор поддерживаемых протоколов (TCP, UDP или оба).
*   **Bond Inbound:** виртуальный Inbound-агрегатор, объединяющий несколько других входящих портов в единый логический пул.
    *   *Специфичные настройки:*
        *   `Inbounds` (Список входящих): выбор тегов существующих Inbound-портов, трафик с которых будет объединен и направлен по общим правилам.
*   **Core Failover Inbound:** виртуальный входящий шлюз для обеспечения нативной отказоустойчивости входящих соединений.
    *   *Специфичные настройки:*
        *   `Inbounds` (Список входящих): выбор тегов входящих портов, для которых ядро будет обеспечивать резервирование сокетов на системном уровне.

## 3. Outbounds (Исходящие подключения) по протоколам

Исходящие подключения определяют путь отправки трафика во внешнюю сеть. Ниже описаны параметры каждого исходящего протокола.

*   **direct (Прямое подключение):** отправляет трафик напрямую через сетевой интерфейс сервера без проксирования и шифрования.
    *   `Override Address` (Переопределение адреса): принудительное изменение IP-адреса назначения для всех исходящих пакетов.
    *   `Override Port` (Переопределение порта): принудительное изменение порта назначения.
*   **block (Блокировка):** блокирует сетевые пакеты. Запросы к целевым ресурсам сбрасываются. Дополнительных полей для настройки не требуется.
*   **socks (Socks Client):** подключение к удаленному Socks4, Socks4a или Socks5 прокси.
    *   `Server` (Адрес сервера) и `Server Port` (Порт): адрес и порт удаленного прокси.
    *   `Username` (Имя) и `Password` (Пароль): авторизация на прокси-сервере.
    *   `Version` (Версия): выбор версии протокола (`4`, `4a`, `5`).
    *   `UoT` (UDP over TCP): инкапсуляция UDP-пакетов в TCP для прохождения ограничений провайдеров.
*   **http (HTTP Client):** подключение к HTTP-прокси.
    *   `Server` и `Server Port`: адрес и порт сервера.
    *   `Username` и `Password`: авторизация Basic Auth.
    *   `Headers` (Заголовки): кастомные HTTP-заголовки для отправки удаленному прокси.
    *   `Path` (Путь): адрес пути в HTTP-запросе проксирования.
*   **shadowsocks (Shadowsocks Client):** классический защищенный прокси.
    *   `Method` (Метод шифрования): выбор алгоритма (рекомендуется `2022-blake3-aes-128-gcm`).
    *   `Password` (Пароль): ключ авторизации.
    *   `Plugin` (Плагин): выбор плагина обфускации, например `obfs-local` или `v2ray-plugin`.
    *   `Plugin Options` (Параметры плагина): строка параметров плагина (например, `obfs=http;obfs-host=yandex.ru`).
*   **vmess (VMess Client):** клиентское подключение V2Ray VMess.
    *   `UUID`: уникальный идентификатор пользователя.
    *   `Alter ID`: число альтернативных идентификаторов (рекомендуется устанавливать значение `0`).
    *   `Security`: тип шифрования сессии (`auto`, `none`, `zero`, `aes-128-gcm`, `chacha20-poly1305`).
    *   `Packet Encoding`: упаковка UDP-трафика (`none`, `packetaddr`, `xudp`).
    *   `Global Padding`: включение глобального заполнения пакетов для защиты от DPI.
    *   `Authenticated Length`: шифрование длины пакета для защиты от активного зондирования.
*   **vless (VLESS Client):** современный легкий протокол без шифрования на уровне прокси.
    *   `UUID`: уникальный идентификатор пользователя.
    *   `Flow`: тип управления потоком данных. Для Reality используется значение `xtls-r-ux-y` или аналогичные.
    *   `Decryption`: значение шифрования (всегда устанавливается `none`).
*   **trojan (Trojan Client):** маскировка трафика под HTTPS.
    *   `Password`: пароль доступа к прокси.
*   **naive (NaiveProxy Client):** использование сетевого стека Chrome для идеальной маскировки.
    *   `Username` и `Password`: параметры авторизации.
*   **tor (Tor Outbound):** направление исходящего трафика через локальную или удаленную сеть Tor.
    *   `Tor RC Path` (Путь к конфигу): путь к конфигурационному файлу Tor.
    *   `Tor Instance`: запуск отдельного встроенного инстанса Tor.
*   **ssh (SSH Client):** туннелирование через SSH-соединение.
    *   `User` (Пользователь) и `Password` (Пароль): учетные данные SSH.
    *   `Private Key` (Приватный ключ): содержимое ключа авторизации SSH.
    *   `Private Key Passphrase`: пароль для расшифровки приватного ключа хоста.
    *   `Host Key` (Ключ хоста): публичный ключ удаленного сервера для проверки подлинности.
*   **shadowtls (ShadowTLS Client):** защита соединения с помощью имитации TLS-сессии.
    *   `Password` (Пароль): ключ проверки подлинности.
    *   `Version` (Версия): выбор версии протокола (`1`, `2`, `3`).
*   **anytls (AnyTLS Client):** защищенный клиент с кастомными параметрами маскировки TLS.
    *   `Password`: пароль доступа.
    *   `Padding Scheme`: схема заполнения мусорными байтами для изменения длины пакетов.
*   **mieru (Mieru Client):**
    *   `Username` и `Password`: данные пользователя.
    *   `Multiplexing` (Мультиплексирование): режим сжатия и объединения сессий.
    *   `Server Ports` (Порты сервера): доступные порты для связи с сервером.
    *   `Traffic Pattern` (Шаблон трафика): конфигурация маскировки активности.
*   **trusttunnel (TrustTunnel Client):**
    *   `Username` и `Password`: данные для авторизации.
    *   `QUIC`: включение транспорта QUIC.
    *   `Congestion Controller`: выбор алгоритма управления очередью (например, `bbr`).
    *   `BBR Profile`: выбор профиля BBR (стандартный, консервативный или агрессивный).
*   **sudoku (Sudoku Client):**
    *   `Key` (Ключ): секрет для авторизации.
    *   `AEAD Method`: метод шифрования.
    *   `Table Type`: тип подстановочной таблицы.
    *   `HTTP Mask`: параметры маскировки под веб-запросы (включает поля `enabled`, `mode`, `multiplex`, `host`, `path_root`).
*   **masque (Masque Client):** подключение по новому маскировочному протоколу MASQUE на базе HTTP/3.
*   **openvpn (OpenVPN Client):** интеграция с серверами OpenVPN.
    *   `Config Path` (Путь к конфигурации): путь к файлу конфигурации `.ovpn`.
*   **hysteria / hysteria2 (Hysteria Client):** транспорт на базе UDP/QUIC для работы на нестабильных каналах.
    *   `Obfs` (Обфускация): пароль обфускации для скрытия QUIC-заголовков.
    *   `Upload / Download Mbps`: лимиты скорости для корректного расчета пропускной способности алгоритмом BBR.
*   **tuic (TUIC Client):** быстрое QUIC-подключение.
    *   `UUID` и `Password`: данные для авторизации.
    *   `Congestion Control`: контроллер перегрузок (`cubic`, `new_reno`, `bbr`).
    *   `Zero-RTT Handshake`: включение немедленной отправки данных без ожидания TLS-ответа.

## 4. Параметры сетевого набора (Dial Options) в Outbounds

Параметры Dial Options отвечают за инициализацию исходящих сокетов. Для отображения скрытых полей нажмите кнопку "Dial Options" в настройках Outbound.

*   **Detour (Обход):** перенаправление исходящего соединения через другой прокси (создание цепочки прокси-серверов).
*   **Bind Interface:** привязка исходящего сокета к физическому сетевому интерфейсу сервера.
*   **Inet4 Bind Address / Inet6 Bind Address:** жесткое указание исходящего IPv4 или IPv6 адреса сервера для отправки пакетов.
*   **Bind Address No Port:** позволяет системе автоматически выбирать свободный порт для привязки.
*   **Protect Path:** путь к сокету на Android-устройствах для исключения VPN-петли.
*   **Routing Mark:** системная метка для таблиц маршрутизации ядра Linux.
*   **Reuse Addr:** разрешение повторного использования локального порта при исходящем подключении.
*   **Network Namespace (netns):** запуск исходящего сокета в изолированном пространстве имен Linux.
*   **TCP Fast Open (TFO):** включение TFO для исходящих соединений.
*   **TCP Multi Path:** использование нескольких каналов связи одновременно для передачи TCP.
*   **Disable TCP Keep Alive:** отключение отправки проверочных пакетов.
*   **TCP Keep Alive / TCP Keep Alive Interval:** настройка частоты проверок неактивного соединения.
*   **UDP Fragment:** разрешение на фрагментацию исходящих UDP пакетов.
*   **Connect Timeout:** время ожидания установки соединения в секундах.
*   **Domain Resolver:** выбор конкретного DNS-сервера для разрешения имени прокси-сервера.
*   **Domain Strategy:** стратегия разрешения доменных имен при отправке пакетов.
*   **Fallback Delay:** задержка в миллисекундах перед запуском резервного IPv4-подключения при медленном ответе по IPv6 (режим Happy Eyeballs).
*   **Fallback Network Type / Network Type:** выбор протоколов транспортного уровня (TCP, UDP или оба).
*   **Network Strategy:** стратегия выбора интерфейса при наличии нескольких сетей.
*   **Idle Session Timeout:** время неактивности сессии до ее автоматического закрытия.
*   **Idle Session Check Interval:** частота проверки неактивных сессий.
*   **Min Idle Session:** минимальное число сессий, которые система удерживает открытыми для мгновенной передачи данных.

## 5. Endpoints (Сетевые точки)

Сетевые точки служат для интеграции сторонних туннелей непосредственно в ядро sing-box. Это позволяет использовать другие VPN-технологии как исходящие каналы для маршрутизации трафика пользователей.

### WireGuard (Warp)
Интегрирует протокол WireGuard (включая сервис Cloudflare Warp) в сетевой стек прокси.
*   **Что делает:** создает виртуальный зашифрованный туннель к серверу WireGuard. Весь направленный в него трафик выходит в интернет с IP-адреса этого удаленного сервера.
*   **Когда используется:**
    *   Для обхода геоблокировок зарубежных сайтов без покупки дополнительных VPS в разных странах.
    *   Для маскировки трафика вашего сервера при обращении к внешним ресурсам.
    *   Для перенаправления трафика к заблокированным в вашей стране ресурсам (например, медиасервисам) через бесплатную сеть Cloudflare Warp.
*   **Рекомендации:** настройте правило в меню Rules, направляющее трафик к заблокированным доменам на этот Endpoint. Это позволит вашим клиентам открывать такие ресурсы без замедления остального интернета.
*   **Параметры:**
    *   `Private Key`: приватный ключ клиента.
    *   `Server / Server Port`: адрес и порт сервера подключения (например, серверов Cloudflare Warp).
    *   `Addresses`: виртуальные IP-адреса, выданные клиенту (через запятую).
    *   `Reserved`: массив зарезервированных байт для прохождения проверок Warp.
    *   `MTU`: максимальный размер пакета (обычно `1280` или `1420`).

### Tailscale
Интегрирует ваш сервер в приватную mesh-сеть Tailscale.
*   **Что делает:** позволяет серверу общаться с вашими домашними ПК, телефонами и другими серверами внутри единой защищенной сети без открытия портов во внешний интернет.
*   **Когда используется:**
    *   Для организации безопасного канала администрирования. Вы можете привязать веб-интерфейс панели s-ui-x к внутреннему IP-адресу Tailscale, полностью закрыв доступ из публичного интернета.
    *   Для связи распределенных серверов баз данных и бэкапов.
*   **Рекомендации:** используйте Tailscale совместно со встроенной службой derp для надежного обхода жестких брандмауэров (NAT) ваших клиентов.
*   **Параметры:**
    *   `Auth Key`: ключ авторизации для регистрации ноды в вашей панели Tailscale.
    *   `Control URL`: адрес управляющего сервера (по умолчанию используется официальный сервер Tailscale или ваш собственный Headscale).

### VPN
Интегрирует стандартные клиент-серверные VPN-соединения.
*   **Что делает:** подключает sing-box к внешним серверам VPN.
*   **Когда используется:** при необходимости пустить трафик определенных клиентов через корпоративный VPN-туннель.
*   **Параметры:** настройки виртуального клиент-серверного VPN подключения.

## 6. Services (Встроенные службы)

Встроенные службы выполняют системные задачи, такие как управление системным DNS, мониторинг ресурсов, отладка и координация распределенных нод.

### resolved
Интеграция с системным демоном разрешения имен systemd-resolved в Linux.
*   **Что делает:** автоматически транслирует правила DNS, настроенные внутри sing-box, в операционную систему сервера.
*   **Когда используется:** при запуске sing-box в режиме прозрачного прокси (TUN/TProxy). Это предотвращает конфликты за порт 53 и защищает от утечек DNS на уровне ОС.
*   **Рекомендации:** включайте resolved всегда при настройке системного туннелирования Tun для избежания некорректной работы локальных служб сервера.
*   **Параметры:** дополнительных полей для настройки не требует.

### ssm-api
Внутренний интерфейс мониторинга.
*   **Что делает:** предоставляет программный интерфейс (API) для чтения показателей нагрузки и трафика панели.
*   **Когда используется:** для интеграции с внешними системами мониторинга (например, Prometheus, Grafana).

### derp
Запуск встроенного сервера обхода NAT (Designated Encrypted Relay for Packets).
*   **Что делает:** выступает в качестве промежуточного реле-сервера для шифрованного трафика Tailscale.
*   **Когда используется:** если два устройства в сети Tailscale находятся за строгими брандмауэрами (Symmetric NAT) и не могут соединиться напрямую. В этом случае они общаются через этот derp-сервер.
*   **Рекомендации:** запускайте derp на серверах с хорошей пропускной способностью и низким пингом для обеспечения комфортной связи между вашими удаленными устройствами.
*   **Параметры:**
    *   `Port`: порт службы.
    *   `STUN Port`: порт для STUN запросов (обычно UDP `3478`).

### ocm / ccm
Координаторы распределенных конфигураций.
*   **Что делает:** обеспечивает синхронизацию файлов конфигураций и прав пользователей между несколькими серверами (нодами).
*   **Когда используется:** в крупных сетях прокси, где один администратор управляет кластером серверов из одной панели.

### oom-killer
Встроенный предохранитель оперативной памяти.
*   **Что делает:** непрерывно измеряет потребление RAM процессом sing-box. При превышении лимита принудительно и безопасно перезапускает процесс.
*   **Когда используется:** для защиты сервера от падения при утечках памяти, которые могут возникать в тяжелых конфигурациях (например, при сотнях активных клиентов на протоколах gRPC или WebSocket с шифрованием Reality).
*   **Рекомендации:** устанавливайте лимит памяти примерно на 80 процентов от общего объема свободной оперативной памяти вашего VPS.
*   **Параметры:**
    *   `Memory Limit`: порог оперативной памяти, при превышении которого служба безопасно перезапускает sing-box.

### profiler
Инструмент профилирования производительности.
*   **Что делает:** запускает сервер сбора метрик pprof (использование CPU, количество аллокаций памяти, стек вызовов функций).
*   **Когда используется:** разработчиками для поиска узких мест производительности и отладки ядра.
*   **Рекомендации:** держите эту службу отключенной в рабочей среде. Включайте ее только при расследовании аномальной нагрузки на процессор.
*   **Параметры:**
    *   `Port`: порт отладки (доступен локально).

## 7. TLS Settings (Параметры шифрования)

Профили TLS настраивают защиту сетевых каналов.

### Серверные настройки (Server TLS)
Используются в Inbounds для приема зашифрованных соединений.
*   **Certificate (CRT) и Private Key (KEY):** файлы сертификата и ключа.
*   **ALPN:** список поддерживаемых протоколов прикладного уровня (например, `h2`, `http/1.1`).
*   **Min Version / Max Version:** выбор поддерживаемых версий TLS (рекомендуется `1.2` и `1.3`).
*   **Cipher Suites:** выбор разрешенных алгоритмов шифрования.

### Клиентские настройки (Client TLS)
Используются в Outbounds для подключения к защищенным серверам.
*   **Server Name (SNI):** имя хоста для проверки сертификата.
*   **Insecure:** отключает проверку подлинности сертификата сервера (не рекомендуется в рабочих окружениях).
*   **Disable Session Resumption:** отключает повторное использование параметров предыдущих сессий TLS.

### Совместимость протоколов с TLS и Reality

При создании профилей шифрования важно учитывать, какие протоколы поддерживают классический TLS (требующий SSL сертификаты), а какие совместимы с технологией Reality (маскировка под сторонние доверенные сайты).

#### Протоколы с поддержкой классического TLS
Классический TLS шифрует канал с помощью пары ключей и сертификата, выписанного на доменное имя. Он поддерживается следующими протоколами:
*   **VLESS, VMess, Trojan:** основные прокси протоколы при работе через транспорт TCP, WebSocket или gRPC.
*   **Hysteria 2 / TUIC:** протоколы на базе UDP/QUIC. Они требуют наличия классического SSL сертификата для защиты сессий. ВНИМАНИЕ: Reality с ними не работает, так как Reality требует транспортного уровня TCP для перехвата рукопожатий.
*   **NaiveProxy:** использует веб сервер Caddy или стек Chromium, для которых необходим стандартный TLS сертификат.
*   **Socks / HTTP:** могут быть обернуты в TLS транспорт для шифрования трафика между клиентом и прокси.
*   **ShadowTLS, AnyTLS, TrustTunnel:** используют сертификаты для имитации или создания защищенного TLS канала.

#### Протоколы с поддержкой Reality
Технология Reality устраняет необходимость покупки и обновления доменных имен и SSL сертификатов. Она перехватывает запросы клиентов и маскирует их под обычное TLS рукопожатие с крупным доверенным ресурсом. Reality поддерживается следующими протоколами:
*   **VLESS:** наиболее популярное и стабильное сочетание (VLESS + Reality + XTLS). Рекомендуется для обхода блокировок.
*   **Trojan:** sing-box поддерживает маскировку Reality для протокола Trojan.
*   **VMess:** также поддерживает интеграцию с Reality на транспортном уровне TCP.

*Ограничение Reality:* протоколы, работающие на базе UDP/QUIC (такие как Hysteria и TUIC), технически несовместимы с Reality.

## 8. Rules (Маршрутизация) и Rule Sets

Маршрутизатор направляет пакеты на основе заданных условий.

### Поля параметров в Rules
*   **Inbound:** фильтрация по тегу входящего порта.
*   **Client:** фильтрация по имени пользователя прокси.
*   **Domain / Domain Suffix / Domain Keyword / Domain Regex:** фильтрация доменов по совпадению, суффиксу, ключевому слову или регулярному выражению.
*   **IP / CIDR:** IP-адреса назначения (например, `8.8.8.8` или `192.168.0.0/16`).
*   **Source IP / Source CIDR:** IP-адреса отправителя.
*   **Port / Source Port:** порты назначения и отправителя.
*   **Protocol:** тип трафика (`http`, `tls`, `quic`, `dns`, `bittorrent`).
*   **Rule Sets:** внешние подключаемые базы правил.
*   **Outbound:** тег исходящего подключения, куда направляется совпавший трафик.

## 9. DNS Settings (Настройка DNS)

Резолвер отвечает за преобразование имен хостов в IP-адреса.

```
                   Запрос DNS от клиента
                             |
                   Проверка правил DNS
                             |
             +---------------+---------------+
             | Совпало                       | Не совпало
             v                               v
   Направлен на указанный          Направлен на дефолтный
     сервер (например, DoH)          DNS (Final DNS)
```

### Настройка DNS-серверов
*   **Address:** адрес сервера. Поддерживаются обычные IP (`8.8.8.8`), DoT (`tls://1.1.1.1`) и DoH (`https://dns.google/dns-query`).
*   **Detour (Обход):** тег Outbound-прокси, через который идет запрос к этому серверу. Это предотвращает блокировку DNS-запросов вашим провайдером.
*   **Client Subnet:** передача подсети клиента для географической оптимизации ответов.

### Настройка правил DNS (DNS Rules)
Правила DNS определяют, какой DNS-сервер опрашивать для конкретного домена.
*   **Domain / Domain Suffix:** списки доменов для этого правила.
*   **Server:** выбор DNS-сервера для совпавших доменов.
*   **Disable Cache:** отключение кэширования ответов для этого правила.

## 10. Балансировка, резервирование и переключение трафика

Панель и ядро sing-box предоставляют несколько способов организации отказоустойчивости.

### Selector (Ручной выбор)
Классическая группа, где конечный сервер выбирается пользователем вручную в приложении-клиенте.
*   *Параметры:*
    *   `tag` означает уникальный тег группы.
    *   `outbounds` означает список тегов входящих в группу серверов.

### URLTest (Автоматический выбор по задержке)
Ядро периодически измеряет время отклика серверов и автоматически направляет трафик на самый быстрый.
*   *Обязательные поля:*
    *   `url` означает тестовый адрес запроса (обычно `https://www.gstatic.com/generate_204`).
    *   `interval` означает частоту проверок (например, `3m` для периода раз в три минуты).
    *   `tolerance` означает порог чувствительности в миллисекундах (например, `50ms`). Если разница между серверами меньше этого значения, переключение не происходит. Это защищает от частой смены серверов при равном пинге.

### Fallback (Резервирование на этапе подключения)
Переключение происходит в момент сбоя при установке соединения (dial-time).
*   *Логика работы:* Ядро пытается установить соединение через первый сервер в списке. Если он недоступен, запрос мгновенно перенаправляется на второй, затем на третий. Фоновые теги пинга здесь не используются.
*   *Параметры:* список `outbounds`, отсортированный по приоритету.

### Failover (Панельный управляемый приоритет)
Улучшенный механизм отказоустойчивости, контролируемый бэкендом панели.
*   *Логика работы:* Панель опрашивает серверы через встроенную службу проверки. При падении основного сервера группа переключается на резервный. Новые TCP и UDP соединения идут через новый рабочий сервер, старые сессии на упавшем сервере могут разорваться.
*   *Hysteresis (Гистерезис):* количество успешных проверок подряд (например, `2`), которое сервер должен пройти перед тем, как панель вернет его в список активных. Защищает от ложных переключений при нестабильном качестве связи.
*   *All Down Policy (Действие при падении всех серверов):*
    *   `hold_current` означает продолжать слать запросы на последний использованный сервер.
    *   `block` означает полностью заблокировать трафик группы.
    *   `direct` означает пустить трафик напрямую без прокси. Будьте осторожны: это раскрывает реальный IP-адрес сервера.

### Bond (Агрегация каналов)
Объединение нескольких прокси-серверов в один виртуальный канал.
*   *Режимы работы:*
    *   `balance-rr` (Round-Robin) означает, что пакеты отправляются поочередно через все серверы группы, позволяя суммировать скорость при многопоточной загрузке.
    *   `active-backup` означает, что работает один основной сервер, а резервный подключается только при аварии первого.

### CoreFailover (нативный failover ядра)
Нативный failover sing-box для выбора участника во время dial. В панели этот тип называется `core-failover`, а при сборке конфигурации сериализуется в нативный `type: failover` ядра.

### Parser (Автоматический парсер ссылок)
Исходящий виртуальный протокол, который принимает на вход стороннюю ссылку подписки (например, vless или shadowsocks) и автоматически конвертирует ее во внутренний формат конфигурации sing-box.

## 11. Лимитеры и ограничения (Limiters)

Лимитеры представляют собой специальные прокси-обертки (outbounds) для контроля параметров трафика клиентов.

*   **BandwidthLimiter (Ограничение скорости):**
    *   `speed` означает максимальную скорость в байтах в секунду (например, `1048576` для 10 Мбит/с).
    *   `mode` означает тип лимита: `sum` (общая сумма входящей и исходящей скорости) или `separated` (раздельные лимиты на прием и отдачу).
*   **ConnectionLimiter (Ограничение сессий):**
    *   `count` означает максимальное количество одновременно открытых TCP-соединений и UDP-потоков на одного пользователя (защита от DDoS и спам-рассылок).
*   **TrafficLimiter (Лимит объема данных):** автоматическое отключение клиента при превышении лимита трафика (например, 100 ГБ в месяц).
*   **RateLimiter (Частота запросов):** ограничение количества новых запросов в секунду (PPS) для защиты DNS и API.
*   **Block:** полная блокировка трафика для выбранного профиля.

## 12. Практические сценарии настройки протоколов

### Сценарий 1: Настройка VLESS-Reality (Максимальная маскировка трафика)
1.  **Настройка TLS:**
    *   Перейдите в **TLS Settings**, нажмите *Добавить*.
    *   Выберите тип **Reality**.
    *   Задайте домен маскировки в поле `Dest` (например, `images.apple.com:443`) и укажите `Server Names` (`images.apple.com`).
    *   Нажмите кнопку *Generate Keys* для создания ключей. Скопируйте публичный ключ.
    *   Задайте любой случайный hex в поле `Short IDs` (длиной от 2 до 16 символов). Сохраните профиль.
2.  **Настройка входящего соединения (Inbound):**
    *   Перейдите в **Inbounds**, нажмите *Добавить*.
    *   Выберите тип **vless**.
    *   Укажите порт `443` и выберите созданный ранее профиль TLS Reality.
    *   Включите опции **Sniff** и **Sniff Override Destination**. Сохраните Inbound.
3.  **Добавление клиента:**
    *   Перейдите во вкладку **Clients**, добавьте пользователя, привязав его к созданному Inbound.
    *   Скопируйте сгенерированную ссылку или QR-код. Панель автоматически подставит в ссылку UUID клиента, публичный ключ Reality и правильный SNI домена маскировки.

### Сценарий 2: Настройка Shadowsocks (Классический быстрый прокси)
1.  **Настройка входящего соединения (Inbound):**
    *   Перейдите в **Inbounds**, нажмите *Добавить*.
    *   Выберите тип **shadowsocks**.
    *   Выберите метод шифрования (рекомендуется современный `2022-blake3-aes-128-gcm`).
    *   Задайте пароль. Панель сгенерирует криптографически стойкий ключ автоматически при нажатии кнопки генерации.
2.  **Маршрутизация:**
    *   Создайте правило в **Rules**, направляющее трафик с этого Inbound на нужный Outbound (например, на `direct` для использования сервера как прокси или на другой прокси-сервер для создания цепочки).

### Сценарий 3: Настройка ShadowTLS со скрытым Shadowsocks
Этот сценарий защищает Shadowsocks от активного сканирования блокировщиками.
1.  **Создание внутреннего Shadowsocks:**
    *   Создайте Inbound с типом **shadowsocks**.
    *   В поле `Listen Address` укажите `127.0.0.1` (это скроет порт от внешнего интернета).
    *   Выберите метод шифрования (например, `2022-blake3-aes-128-gcm`), сгенерируйте пароль и задайте порт (например, `10001`). Запомните тег этого Inbound, например `ss-inner`.
2.  **Создание внешнего ShadowTLS:**
    *   Создайте Inbound с типом **shadowtls**.
    *   Укажите внешний порт (например, `8443`).
    *   В поле `detour` выберите тег внутреннего Shadowsocks (`ss-inner`).
    *   В параметрах TLS укажите домен для маскировки (например, `cloudflare.com`). Сохраните настройки.
3.  **Импорт клиентом:** При получении ссылки подписки клиентское приложение будет обращаться на порт ShadowTLS (`8443`), проходить проверку подлинности TLS-сессии, после чего расшифрованный поток будет автоматически перенаправлен на порт `10001` локального Shadowsocks.

## 13. Системные механизмы и обслуживание

### Система подписок и безопасность (Sub Secrets)
*   Для предотвращения подбора конфигураций серверов каждому клиенту генерируется уникальный секретный токен (`subSecret`).
*   Ссылка на подписку выглядит как `https://domain.com/sub/client_secret`.
*   При включении опции `subSecretRequired` старые ссылки по именам пользователей блокируются бэкендом.
*   Ответы сервера подписок шифруются gzip при поддержке клиентом и защищены заголовками `no-store` для исключения кэширования провайдерами.

### Мониторинг IP-адресов клиентов
*   Панель не хранит IP-адреса клиентов в открытом виде для обеспечения конфиденциальности. При подключении IP-адрес хэшируется с солью на уровне бэкенда (`IP Hash`).
*   Если у клиента в параметре `ipLimitMode` выбран режим **Enforce**, то при превышении лимита устройств (например, разрешено 2 устройства, а подключается третье) новые сессии с третьего устройства блокируются. При этом сессии первых двух устройств продолжают работать без разрывов.

### Обновление панели и резервное копирование
*   **Резервное копирование:** Панель считывает файл базы данных SQLite и отправляет его клиенту процессом потока прямо с диска. Это исключает перегрузку оперативной памяти сервера при больших базах данных.
*   **Автообновление:** При инициации обновления панель скачивает новый бинарный файл, сверяет его SHA-256 хеш и делает пробный запуск во временной директории. Если запуск прошел успешно, происходит замена основного файла и перезапуск службы. Если новый файл выдает ошибки запуска, панель автоматически откатывается на предыдущую рабочую версию.

## 14. Диагностика неполадок

*   **Ошибка `bind: address already in use`:** Порт входящего соединения занят другим процессом на сервере. Проверьте список занятых портов командой `ss -tulpn` в консоли Linux и измените порт в настройках Inbound.
*   **Ошибка `permission denied` на портах 80 / 443:** Linux запрещает непривилегированным процессам слушать порты ниже 1024. Запустите панель от имени администратора (root) или выдайте права исполняемому файлу командой `setcap 'cap_net_bind_service=+ep' /usr/local/bin/s-ui`.
*   **Утечки DNS (DNS Leak):**
    1.  Проверьте наличие правила перенаправления трафика порта 53 на системный Outbound `dns` в меню **Rules**.
    2.  Проверьте параметр `Domain Strategy` в меню DNS. При наличии IPv6 у клиента установите стратегию `prefer_ipv4` или настройте работу с IPv6 DNS-сервером.
    3.  Убедитесь, что на входящих подключениях включена опция **Sniff** для анализа доменных имен.

## 16. Глоссарий терминов

*   **SNI (Server Name Indication):** текстовое поле в первом пакете TLS рукопожатия, в котором клиент передает доменное имя запрашиваемого сайта. Системы DPI используют его для фильтрации ресурсов.
*   **ALPN (Application-Layer Protocol Negotiation):** расширение TLS, позволяющее клиенту и серверу согласовать протокол прикладного уровня (например, HTTP/2 или HTTP/1.1) без дополнительных сетевых запросов.
*   **CIDR (Classless Inter-Domain Routing):** бесклассовая адресация сетей. Запись вида `192.168.1.0/24` задает подсеть с маской `255.255.255.0`.
*   **BBR (Bottleneck Bandwidth and RTT):** современный алгоритм контроля перегрузки сетевого канала от Google. Он оценивает реальную емкость сети и задержку, не допуская искусственных потерь пакетов.
*   **FWMARK (Flow Mark):** системная метка пакета, устанавливаемая ядром операционной системы для управления сложной маршрутизацией.
*   **Netns (Network Namespace):** технология ядра Linux для изоляции сетевых интерфейсов, таблиц маршрутизации и правил брандмауэра.
*   **EDNS0 (Extension Mechanisms for DNS):** расширение DNS, позволяющее передавать в запросе подсеть клиента для получения географически близких IP адресов серверов CDN.
*   **DPI (Deep Packet Inspection):** технология глубокого анализа содержимого сетевых пакетов провайдерами для обнаружения сигнатур прокси протоколов.

## 17. Чек-лист безопасности и тестирования

Для проверки стабильности и защиты сервера выполните следующие шаги.

1.  **Проверка утечек оригинального IP (IP Leak Test):**
    *   Откройте специализированный сайт (например, `ipleak.net` или `whoer.net`) через настроенный прокси.
    *   Убедитесь, что сайты видят только IP-адрес вашего сервера, а не ваш домашний или мобильный адрес.
2.  **Проверка утечек DNS (DNS Leak Test):**
    *   Запустите расширенный тест на утечку DNS (например, на `dnsleaktest.com`).
    *   В результатах тестирования должны отображаться только DNS серверы, настроенные в панели (или серверы хостинга вашего прокси). Не должно быть серверов вашего реального интернет провайдера.
3.  **Защита панели управления:**
    *   Включите обязательное шифрование HTTPS для доступа к веб интерфейсу панели (вкладка Security в Settings).
    *   Включите параметр `subSecretRequired` в меню настроек для защиты ссылок подписок от сканирования.
4.  **Проверка лимита устройств:**
    *   Попробуйте подключиться к прокси с трех разных устройств одновременно при установленном лимите в два IP.
    *   Третье устройство должно получить ошибку подключения, при этом первые два устройства должны продолжать стабильно работать.

## 18. Различия схожих сетевых механизмов

### CoreFailover vs Failover (панельный)
Эти группы служат для переключения на резервные серверы при аварии, но работают на разных уровнях:
*   **CoreFailover (уровень ядра):** нативное переключение sing-box. Оно срабатывает в момент сетевого вызова сокета (dial-time). Если сокет сообщает об ошибке сети, ядро пробует следующий адрес. Это происходит мгновенно для каждого нового запроса без проведения предварительных фоновых тестов. Подходит для минимизации потерь трафика при временных разрывах.
*   **Failover (уровень панели):** высокоуровневый алгоритм. Панель регулярно (например, каждые 30 секунд) опрашивает входящие в группу серверы через HTTP запросы. Решение о переключении принимается на основе истории проверок с учетом порога гистерезиса. Оно переключает активный шлюз глобально для всех новых сессий. Предоставляет администратору детальную статистику здоровья серверов.

### Bond vs Selector / URLTest
*   **Bond (агрегация):** объединяет физические прокси-каналы в один виртуальный интерфейс. В режиме Round-Robin пакеты распределяются по всем серверам одновременно. Это увеличивает скорость многопоточной загрузки.
*   **Selector (ручной выбор):** не распределяет трафик, а направляет его через один конкретный сервер, выбранный администратором или пользователем в клиенте.
*   **URLTest (автоматический пинг):** постоянно тестирует задержку и автоматически переключает всю группу на один сервер с наилучшим показателем пинга. В отличие от Bond, здесь трафик идет строго через один выбранный канал.

## 19. Различия Inbound и Outbound для схожих протоколов

Некоторые типы протоколов присутствуют как во входящих (Inbound), так и в исходящих (Outbound) подключениях, но имеют принципиально разные задачи:

*   **Socks / HTTP:**
    *   *Inbound:* открывает порт на вашем сервере, позволяя локальным программам или браузерам использовать его как прокси. Требует привязки к локальному интерфейсу (обычно `127.0.0.1` или `0.0.0.0`) и порт.
    *   *Outbound:* указывает ядру sing-box использовать сторонний Socks или HTTP прокси для выхода в интернет. Требует ввода внешнего адреса и порта этого стороннего прокси.
*   **SSH:**
    *   *Inbound:* запускает встроенный SSH-сервер на указанном порту. Клиенты могут подключаться через стандартные клиенты SSH для проброса портов.
    *   *Outbound:* заставляет ядро sing-box подключиться к удаленному SSH-серверу по протоколу SFTP/SSH и гнать трафик через него.
*   **Direct:**
    *   *Inbound:* принимает трафик на определенном порту и пересылает его без изменений (прозрачный ретранслятор). Используется для проброса портов.
    *   *Outbound:* завершающий этап маршрутизации. Отправляет пакеты в интернет напрямую от имени сетевой карты вашего сервера.

## 20. Подробные инструкции по настройке протоколов

Ниже описаны шаги создания входящих и исходящих подключений для каждого протокола с указанием формата вводимых данных.

### Настройка входящих подключений (Inbounds)

#### VLESS
1.  **Создание TLS:** перейдите в меню TLS Settings и создайте профиль TLS (для обычного VLESS) или Reality (для маскировки под сторонний сайт).
2.  **Заполнение полей Inbound:**
    *   `Type`: выберите `vless`.
    *   `Port`: введите свободный порт, например `443` (для Reality рекомендуется использовать порт `443`).
    *   `Decryption`: введите значение `none`.
    *   `TLS`: выберите созданный профиль TLS или Reality.
3.  **Добавление пользователей:** перейдите во вкладку `Clients`, выберите созданное VLESS подключение и добавьте клиента. UUID сгенерируется автоматически.

### VMess
1.  **Заполнение полей Inbound:**
    *   `Type`: выберите `vmess`.
    *   `Port`: укажите свободный порт, например `10002`.
    *   `UUID`: введите уникальный ключ в формате UUIDv4 (например, `f81d4fae-7dec-11d0-a765-00a0c91e6bf6`). Его можно сгенерировать кнопкой в поле ввода.
    *   `Security`: выберите `auto` (ядро автоматически выберет лучший алгоритм шифрования).
2.  **Транспортная сеть:** выберите тип сети (TCP, WebSocket или gRPC). При выборе WebSocket укажите путь в поле `Path` (например, `/ws`).
3.  **TLS:** при необходимости выберите профиль TLS для шифрования транспортного уровня.

### Trojan
1.  **Заполнение полей Inbound:**
    *   `Type`: выберите `trojan`.
    *   `Port`: укажите свободный порт (обычно используется `443`).
    *   `Fallback Server`: введите адрес локального веб-сервера для маскировки, например `127.0.0.1`.
    *   `Fallback Port`: укажите порт локального веб-сервера, например `80` или `8080`.
2.  **TLS:** обязательно выберите профиль TLS со стандартными сертификатами (Trojan не работает без шифрования).

### Shadowsocks
1.  **Заполнение полей Inbound:**
    *   `Type`: выберите `shadowsocks`.
    *   `Port`: укажите свободный порт, например `10003`.
    *   `Method`: выберите алгоритм шифрования (рекомендуется `2022-blake3-aes-128-gcm`).
    *   `Password`: введите пароль. Для алгоритмов 2022 года пароль должен быть строго определенной длины (16 или 32 байта в формате base64). Нажмите кнопку генерации, чтобы получить совместимый ключ.
    *   `Network`: выберите `tcp` или `udp` (рекомендуется оставить оба значения).

### Socks / HTTP
1.  **Заполнение полей Inbound:**
    *   `Type`: выберите `socks` или `http`.
    *   `Port`: укажите свободный порт (например, `1080` для Socks или `8080` для HTTP).
    *   `Username` и `Password`: введите имя пользователя и пароль для авторизации клиентов. Оставьте поля пустыми, если авторизация не требуется.
    *   `UoT` (для Socks): включите эту опцию, если клиенты будут передавать UDP трафик через TCP соединение.

### Hysteria 2
1.  **Заполнение полей Inbound:**
    *   `Type`: выберите `hysteria2`.
    *   `Port`: укажите UDP порт, например `443` или `20000`.
    *   `Obfs`: при необходимости задайте пароль обфускации в поле `password` для скрытия QUIC заголовков.
2.  **TLS:** выберите профиль TLS со стандартным сертификатом (Reality не поддерживается).
3.  **Пропускная способность:** задайте лимиты скорости в Mbps (например, `100` для отдачи и `100` для загрузки), чтобы алгоритм BBR корректно оптимизировал передачу пакетов.

### TUIC
1.  **Заполнение полей Inbound:**
    *   `Type`: выберите `tuic`.
    *   `Port`: укажите UDP порт.
    *   `Congestion Control`: выберите алгоритм (рекомендуется `bbr`).
    *   `Auth Timeout`: укажите таймаут проверки авторизации, например `3s`.
2.  **TLS:** выберите профиль TLS со стандартным сертификатом.

### NaiveProxy
1.  **Заполнение полей Inbound:**
    *   `Type`: выберите `naive`.
    *   `Port`: укажите свободный порт.
    *   `Username` и `Password`: введите учетные данные пользователя.
2.  **TLS:** выберите профиль TLS со стандартным сертификатом.

### ShadowTLS
1.  **Создание зависимого прокси:** предварительно создайте локальный Shadowsocks Inbound на адресе `127.0.0.1` и порту `10001` (с тегом `ss-inner`).
2.  **Заполнение полей ShadowTLS:**
    *   `Type`: выберите `shadowtls`.
    *   `Port`: укажите внешний порт, например `8443`.
    *   `Detour`: выберите созданный Shadowsocks прокси `ss-inner`.
    *   `Version`: укажите версию протокола (рекомендуется `3`).
    *   `TLS`: укажите домен для маскировки TLS сессий (например, `cloudflare.com`).

### Mieru
1.  **Заполнение полей Inbound:**
    *   `Type`: выберите `mieru`.
    *   `Transport`: выберите тип транспорта.
    *   `Listen Ports`: введите массив портов, которые будет слушать протокол.
    *   `Traffic Pattern`: укажите путь к конфигурационному файлу маскировки трафика.

### Sudoku
1.  **Заполнение полей Inbound:**
    *   `Type`: выберите `sudoku`.
    *   `Key`: задайте секретный ключ авторизации.
    *   `AEAD Method`: выберите метод шифрования, например `chacha20-poly1305`.
    *   `Table Type`: укажите тип подстановочной таблицы.

### TrustTunnel
1.  **Заполнение полей Inbound:**
    *   `Type`: выберите `trusttunnel`.
    *   `Network`: выберите поддерживаемые протоколы.
    *   `QUIC`: включите опцию для работы через UDP QUIC.
    *   `Congestion Controller`: укажите алгоритм, например `bbr`.

### SSH
1.  **Заполнение полей Inbound:**
    *   `Type`: выберите `ssh`.
    *   `Port`: укажите свободный порт (например, `22` или `2222`).
    *   `Host Key Path`: укажите путь к файлу приватного ключа сервера на диске (например, `/etc/ssh/ssh_host_rsa_key`).

### MTProxy
1.  **Заполнение полей Inbound:**
    *   `Type`: выберите `mtproxy`.
    *   `Port`: укажите порт подключения.
    *   `Fronting Host`: укажите домен маскировки (например, `cloudflare.com`).
    *   `Concurrency`: введите количество рабочих потоков, например `2`.

### Tun
1.  **Заполнение полей Inbound:**
    *   `Type`: выберите `tun`.

### Настройка исходящих подключений (Outbounds)

Ниже описаны шаги создания исходящих подключений (Outbounds) для каждого протокола с указанием формата вводимых данных.

1.  **Настройка подключения:**

    *   `Port`: укажите порт удаленного прокси.
    *   `Version`: укажите версию протокола (`4`, `4a` или `5`).
    *   `Username` и `Password`: введите данные учетной записи (оставьте пустыми, если прокси работает без авторизации).

#### http (HTTP Клиент)
1.  **Настройка подключения:**
    *   `Type`: выберите `http`.
    *   `Server`: введите IP адрес или домен удаленного HTTP прокси.
    *   `Port`: укажите порт удаленного прокси.
    *   `Username` и `Password`: введите данные авторизации при необходимости.
    *   `Path`: укажите виртуальный путь проксирования.

#### shadowsocks (Shadowsocks Клиент)
1.  **Настройка подключения:**

## 21. Подробные инструкции по настройке Endpoints

Endpoints (сетевые точки) интегрируют виртуальные сетевые интерфейсы в sing-box.

### WireGuard (Warp)
1.  Создайте сетевую точку, выбрав тип `wireguard`.
2.  Заполните параметры:
    *   `Private Key`: введите закрытый ключ WireGuard в формате base64.
    *   `Server` и `Server Port`: укажите адрес и порт сервера (для Cloudflare Warp обычно используется IP `162.252.172.57` или аналогичный и порт `2408`).
    *   `Addresses`: введите IP адреса, выданные вашему клиенту (например, `172.16.0.2/32`, `2001:db8::2/128`).
    *   `MTU`: укажите максимальный размер пакета, например `1280` или `1420`.
    *   `Reserved` (массив байт): укажите зарезервированные байты при их наличии для прохождения верификации Warp.

### Tailscale
1.  Создайте сетевую точку, выбрав тип `tailscale`.
2.  Заполните параметры:
    *   `Auth Key`: введите ключ авторизации (authkey), созданный в панели управления Tailscale. Это необходимо для добавления ноды в вашу сеть.
    *   `Control URL`: введите адрес управляющего сервера (оставьте пустым для использования стандартного `https://controlplane.tailscale.com`).

### VPN
1.  Создайте сетевую точку, выбрав тип `vpn`.
2.  Настройте параметры сетевого интерфейса и ключи авторизации согласно требованиям вашего удаленного VPN провайдера.

## 22. Подробные инструкции по настройке Services

Встроенные службы расширяют возможности ядра sing-box.

### resolved
1.  Создайте службу, выбрав тип `resolved`.
2.  Дополнительных параметров для заполнения не требуется. Служба автоматически интегрирует DNS настройки sing-box в системный демон systemd-resolved на операционной системе Linux.

### ssm-api
1.  Создайте службу, выбрав тип `ssm-api`.
2.  Используется для экспорта системных метрик. Настройте адрес и порт прослушивания при необходимости.

### derp
1.  Создайте службу, выбрав тип `derp`.
2.  Параметры настройки:
    *   `Port`: укажите TCP порт для входящих запросов.
    *   `STUN Port`: укажите UDP порт для STUN проверок (по умолчанию `3478`).

### ccm / ocm
1.  Создайте службу с типом `ccm` или `ocm`.
2.  Введите параметры адреса управляющего сервера и токены авторизации для синхронизации распределенной конфигурации нод.

### oom-killer
1.  Создайте службу, выбрав тип `oom-killer`.
2.  Параметры настройки:
    *   `Memory Limit`: введите максимальный объем оперативной памяти в байтах (например, `536870912` для 512 МБ). При превышении этого порога служба безопасно перезапустит процесс sing-box.

### profiler
1.  Создайте службу, выбрав тип `profiler`.
2.  Параметры настройки:
    *   `Port`: укажите порт отладки (pprof) для сбора профилей нагрузки. Рекомендуется использовать локальный порт, например `6060`.

## 23. Подробные инструкции по настройке TLS Settings

Раздел настраивает профили шифрования TLS.

### Создание серверного профиля TLS (для Inbounds)
1.  Перейдите в меню TLS Settings и нажмите кнопку добавления.
2.  Заполните поля:
    *   `Name`: укажите уникальное имя профиля (например, `my-cert`).
    *   `Certificate (CRT)`: вставьте содержимое файла публичного сертификата (цепочки сертификатов).
    *   `Private Key (KEY)`: вставьте содержимое файла закрытого ключа.
    *   `ALPN`: укажите список поддерживаемых протоколов (например, `h2,http/1.1`).
    *   `Min Version` и `Max Version`: выберите поддерживаемые версии TLS (рекомендуется `1.2` и `1.3`).

### Создание профиля Reality
1.  Перейдите в меню TLS Settings и выберите тип `Reality`.
2.  Заполните поля:
    *   `Dest`: введите адрес сайта-донора с портом (например, `images.apple.com:443`).
    *   `Server Names`: укажите список маскировочных доменов через запятую.
    *   `Private Key` и `Public Key`: сгенерируйте ключи кнопкой генерации.
    *   `Short IDs`: добавьте хотя бы один случайный hex идентификатор длиной от 2 до 16 символов.

## 24. Подробные инструкции по настройке Rules и Rulesets

Раздел настраивает логику перенаправления пакетов (маршрутизацию).

### Создание правила маршрутизации (Rule)
1.  Перейдите в меню Rules и нажмите *Добавить*.
2.  Заполните условия отбора пакетов:
    *   `Inbound`: выберите один или несколько тегов входящих портов, трафик с которых попадет под это правило.
    *   `Client`: укажите имена пользователей прокси для персональной маршрутизации.
    *   `Domain Suffix`: укажите домены (например, `ru` для перенаправления всех российских сайтов напрямую).
    *   `IP / CIDR`: укажите целевые IP адреса или подсети.
    *   `Protocol`: выберите тип протокола (например, `bittorrent` для блокировки скачивания торрентов).
    *   `Rule Sets`: выберите подключенные списки правил (гео-базы).
3.  `Outbound`: выберите исходящий шлюз, куда направить совпавший трафик (например, `direct` или `block`).

### Создание списка правил (Ruleset)
1.  Перейдите в меню Rulesets и нажмите *Добавить*.
2.  Выберите тип источника:
    *   `local`: укажите путь к локальному файлу формата `.srs` или `.json` на сервере.
    *   `remote`: введите ссылку на удаленный список правил (например, списки гео-баз с GitHub) и настройте интервал обновления.

## 25. Подробные инструкции по настройке DNS Settings

DNS резолвер преобразует доменные имена в IP адреса.

### Настройка DNS серверов
1.  Перейдите во вкладку DNS и добавьте сервер.
2.  Заполните поля:
    *   `Address`: введите адрес сервера. Поддерживаются обычные IP (`8.8.8.8`), DoT (`tls://1.1.1.1`) и DoH (`https://dns.google/dns-query`).
    *   `Detour`: укажите тег Outbound прокси, через который будут отправляться запросы к этому DNS серверу для их защиты.
    *   `Client Subnet`: введите подсеть клиента для оптимизации ответов DNS.

### Настройка правил DNS (DNS Rules)
1.  Перейдите во вкладку DNS Rules и добавьте новое правило.
2.  Настройте условия (например, домены с суффиксом `ru`).
3.  `Server`: укажите DNS сервер, который должен обрабатывать эти домены.

## 26. Подробные инструкции по настройке Settings

Раздел отвечает за конфигурацию панели управления.

### Настройка веб интерфейса
1.  `webListen`: укажите IP адрес для доступа к панели. Для безопасности рекомендуется использовать локальный адрес `127.0.0.1` и проксировать панель через Nginx с HTTPS.
2.  `webPort`: введите порт панели управления (по умолчанию `2095`).
3.  `webPath`: задайте секретный префикс пути (например, `/admin-sui/`), чтобы защитить панель от сканирования.

### Настройка подписок
1.  `subSecretRequired`: включите этот параметр для принудительного использования уникальных токенов в клиентских ссылках.
2.  `subRateLimitPerIP`: укажите максимальное количество запросов к серверу подписок с одного IP адреса в минуту во избежание перегрузки базы данных.

### Резервное копирование
1.  `DB Backup Schedule`: настройте расписание автоматического резервного копирования базы данных.
2.  Введите токен Telegram бот-аккаунта и ID чата для автоматической отправки зашифрованных файлов резервных копий.
